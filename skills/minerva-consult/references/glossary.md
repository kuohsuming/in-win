# 術語總表(Glossary / 受控詞彙)

**用法:全 skill 出現下列詞時,一律採此處的意思與寫法,不自創同義詞。**
新增任何術語或工件時,先在此登錄,再用到主檔——這是維持長期一致的單一來源。
(欄位級的受控詞彙見 `output-profiles.md` 的「受控詞彙」表,此處不重複,只登錄流程、概念、工件與同義對照。)

## 一、流程階段(Phase)

| Phase | 正式名 | 一句話 |
|-------|--------|--------|
| 0 | 分級 Triage | 判斷簡單直接答,或複雜跑完整流程 |
| 0.5 | 入口模式 | 分流:帶問題來走 build,帶既有產物來走 improve(完善它、不另起) |
| 1 | 接收與揣摩補全 | sales 態度:寬大接收 + 主動揣摩、把殘缺訊息還原成完整面 |
| 2 | 確認理解 | 回述理解摘要,拿到討論清楚的需求草稿 |
| 2.5 | 專業評估會議 | 跨職能角度嚴格收斂出真需求,砍過度、抓矛盾、還原偽需求 |
| 2.7 | 外部研究與對標 | AI 當 PM 上網找同質對象,產出對標矩陣,可回流校準需求 |
| 3 | 產出、驗收與比較解法 | 長出幾個不同的解、內審、追溯矩陣、(多方案)推理軌跡樹 |
| 4 | 多視角審查成品 | 動態選審查者審「成品」 |
| 5 | 精煉與反挑戰 | 修問題 + 紅隊打破,收斂 |
| 6 | 交付 | 交付卷宗:成品 + 變更清單 + 殘留風險 |

## 二、核心概念與術語(正式名 + 定義)

- **分級(Triage)** — Phase 0 的動作:right-size,小事不套重流程。
- **入口模式(build / improve)** — Phase 0.5 分流:**build** = 帶問題來、從問題長出解法;**improve** = 帶既有產物來、目的是完善它而非另起一份。對使用者寬、對那份產物嚴。
- **診斷地圖** — improve 模式先產出的體檢:既有產物的優點/缺口/風險/隱含假設,與人確認方向後才逐條改。
- **揣摩補全** — Phase 1 的核心動作:從使用者給的幾個線索,揣摩情境、沿隱藏的軸把整個面**還原**齊全。招式名為「**舉一反三**」。產物全標為提議。
- **重構問題** — 當發現「真問題不在使用者以為的地方」時,把題目本身換掉(創意思考)。
- **回流** — 某發現推翻前面某階段的產物時,**定點退回失效的那一階段、只重做受影響部分**(非從頭再跑)。僅限決策關鍵被推翻時觸發;動已核可項須有新資訊 + 五段式 + 人核可;回頭前先攤「影響半徑」。
- **影響半徑(blast radius)** — 要改某項前,先攤出下游哪些依賴它、會跟著失效,讓人看見代價再決定。
- **收斂(防震盪)** — 一次只收一個觸發器;同階段回流逾約 2 次升級給人裁;邊際遞減即停。
- **活文件(single source of truth)** — 全程唯一的狀態,含 `meta/problem_space/requirements/benchmarks/solutions/ledger` 六區塊;各 Phase 更新它而非各生一份。聊天中是 AI 維持一致性的紀律,非真資料庫。
- **穩定 id + 依賴連結** — 每個條目有不變 id(REQ-3、SOL-A…)與「誰依賴誰」的連結;依賴圖是回流判斷影響半徑與退回點的依據。
- **take_and_loss** — 站在決策者立場的損益,用「換到 X、代價 Y」句式:選這個方案得到什麼、放棄什麼、承擔什麼。多方案、單方案、新舊比較皆須寫,不許只列中性優缺點或只報喜。
- **藍海四動作(消去/減少/提升/創造)** — 取捨與差異化鏡頭,強迫同時想減法與加法;用於 improve 改善方向與 Phase 2.7 對標學習(目標差異化非超越)。產出皆提議、走五段式;消去/減少須附證據、創造須接回真實 pain。詳見 `references/thinking-lenses.md`。
- **策略布局圖(strategy canvas)** — 競爭因素 × 投入高低的曲線圖,搭配藍海四動作,看出你 vs 競品該有的差異形狀。
- **探針式 strawman** — Phase 1 引出工具:反問 2–3 輪後主動拋一個「故意留洞的靶」讓人打,用批評釣出隱性邊界(被打臉即成功)。方向模糊用雙靶(相反兩極)。核心動作:每句批評即時翻譯成邊界並回填活文件。詳見 `references/thinking-lenses.md`。
- **讀言外之意(結論還原 + 讀顧慮 + 外部案例)** — Phase 1 F 節:F1 結論式陳述(「失敗了/太貴/試過了」)追問還原成原因/邊界/反例;F2 顧慮(話沒說盡)讀成隱藏約束,標推測、用假設語氣或台階降低表達成本,尊重「不想說」、力道極輕、不做心理分析;F3 引用他人案例(「小明也這麼做」)當可查證的假設,查類比、挖背後真需求、還原偽需求,不順從也不反射反對。
- **邊界追問** — 貫穿硬規則:釐清決策空間「什麼可動(旋鈕)、什麼不可動(牆)」;內容依實際問題而定,是必問方向、非固定清單。
- **逼具體** — 貫穿硬規則:遇抽象詞(盡快/更好/大家…)追問到有數字/日期/範例/名字。「沒有具體錨點的答案 = 還沒回答」。
- **統一把關鐵律** — 任何進出「已確認需求集」的變動(揣摩補全新增、或審查刪改),都要走**五段式可決策說明**、人核可才生效。加與減同一套結構、同一個閘門。
- **五段式可決策說明** — 把關的固定說明結構:① 我的理由 ② 情境/原始考量(標為推測,待確認)③ 好處 ④ 代價與我可能看錯的(每條必寫)⑤ 交還你決定(確認/修正/駁回)。**別名:五段式、可決策說明——皆指此。**
- **提議(proposal)** — AI 補出/推出/查到的任何內容,在人核可前一律是提議,不當事實。
- **專業評估會議** — Phase 2.5 的作法:跨職能角色先獨立評估、再攤衝突,喬不定的取捨上交人裁。**別名:跨職能會議、需求審查——皆指此。**

## 三、工件(Artifact:流程中產生、會被傳遞的東西)

| 工件 | 產於 | 是什麼 |
|------|------|--------|
| **缺口表** | Phase 1A | 十個 element 的狀態表(✓ 已明確 / ~ 揣摩可得 / ✗ 缺失) |
| **地圖** | Phase 1C | 揣摩補全後的完整面(成因/需求/解法三面),全攤給人綜覽,標「你已涵蓋 vs 我新浮現(提議)」;供鳥瞰,非勾選表 |
| **需求草稿** | Phase 1–2 末 | 討論清楚、**人可讀的敘事版**需求 |
| **已確認需求集** | Phase 2.5 末 | 經專業評估收斂、人核可、依 profile **格式化**的需求集;給 AI/執行用。**別名:需求集、真需求集——皆指此工件。**(「真需求」是概念:評估時判定「哪些才是真的」;「已確認需求集」是那個判定落成的工件。) |
| **對標矩陣** | Phase 2.7 | 同質對象 × 維度 + 「對我們的啟示」 |
| **追溯矩陣** | Phase 3 | 解法 × 需求:逐條勾稽解法有沒有滿足每條需求(軟性提示) |
| **推理軌跡樹** | Phase 3 | 多方案時,視覺化 AI 的推理分叉與關鍵分岔點;葉節點交人決定 |
| **Solution Profile** | Phase 3 | 解法的輸出格式,分**決策層**(summary/rationale/requirement_fit/vs_alternatives/cost_effort/risks_assumptions/success_metrics)與**執行層**(plan_for_human/plan_for_ai,核可後才展開) |
| **方案比較表** | Phase 3 / 6 | 沿決策判準比各方案強/弱,固定欄 `take_and_loss`;必含「維持現狀」;多方案必出、單方案也攤損益;improve 模式出「逐項改動損益表」或「整份新舊對照表」 |
| **交付卷宗** | Phase 6 | 活文件的面向讀者視圖:摘要→推薦+備選(含比較表/推理樹)→需求依據→外部佐證→殘留風險→ledger→(選定後)執行計畫;末尾附「待你決定」清單 |
| **決策 ledger** | 全程 | 回流與拍板的軌跡:每次為什麼回、改了什麼、誰拍板、哪些已鎖定;交付時呈現結論的演化 |

## 四、標記與分級(固定用字)

- **element 狀態**:`✓ 已明確` / `~ 揣摩可得` / `✗ 缺失或含糊`
- **來源 origin(四值,永遠可辨)**:`user_stated`(使用者原話)/ `ai_inferred`(AI 揣摩)/ `external_found`(外部查到)/ `ai_estimated`(AI 估算,查無公開數據)
- **優先序**:`Must / Should / Could / Won't`
- **審查嚴重度**:`[阻斷級] / [重大] / [次要]`
- **需求告警類型**:`[阻斷] / [過度] / [偽需求] / [缺口]`
