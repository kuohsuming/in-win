# Minerva Consult —— 使用說明(給使用者)

> 這份是給「人」看的。技術指令在 `SKILL.md`,術語在 `references/glossary.md`。

## 這是什麼

一套幫你**把模糊、複雜或高風險的請求想清楚、再產出可決策方案**的流程。
它以密涅瓦(Minerva)四大思考原則為底,做四件事:

1. **像業務接客一樣「寬」地接住你**——你只要講得出幾個方向、症狀或想法就好,它會主動揣摩你沒說完的部分,把整個問題與需求的面補齊給你看。
2. **像跨職能團隊一樣「嚴」地評估**——用 PM / UX / RD / 財務… 等不同專業角度,判斷哪些才是真需求,砍掉多餘的、抓出矛盾的。
3. **像 PM 做功課一樣去對標**——上網找同類產品、商業模式、前例與失敗案例,讓方案有比較對象。
4. **產出幾個不同的解,並攤開取捨**——每個方案都對回你的需求,多方案時畫出「它為什麼這樣判」的推理圖。

**貫穿全程的一條原則:AI 只提議,你最後拍板。** 它揣摩的、評估的、查到的,都會標成「提議」並解釋理由,由你確認、修改或駁回——它不會替你偷偷做決定。

## 適合 / 不適合用它

- **適合**:需求講不清、想不透的難題、後果重大的決定、要寫規格/提案、想被人從不同角度挑戰。
- **不適合**:簡單事實題、已經很明確的小任務——那些直接問一般 AI 就好,套這套會顯得囉嗦。

## 怎麼開始

- 直接把你的問題丟出來就行,不必先整理好。
- **或帶一份既有的東西來完善它**——proposal、計畫、產品描述、步驟稿都行,說「幫我把這份改好」;它會**體檢並原地補強,不會擅自重寫一份**(除非方向根本錯了,那時它會把新舊兩版並排比較讓你選)。
- 或明確叫用它:「**用 minerva-consult 幫我想清楚 ⋯⋯**」。
- 講得越像「症狀」「煩惱」也沒關係——把它想清楚正是這套流程的工作。

## 過程中會發生什麼

- 它會**反問你**(而且會逼你把「盡快、更好、便宜」這種模糊詞講成具體的數字/日期/範例)。
- 它會**攤一張地圖**給你看它揣摩補全的完整面,再**一次一個重點**跟你討論(不是丟一張清單叫你勾)。
- 每當它想**新增或刪改**一條需求,都會**逐條說明**:為什麼、好處、代價、我可能哪裡看錯——然後交給你決定。

## 你會拿到什麼

一份**可決策的卷宗**,通常包含:釐清後的需求集、外部對標矩陣、幾個不同的解法方案、(多方案時)推理軌跡圖,以及誠實列出的殘留風險與未解問題。

## 幾個好用的操作

- 想加快:說「**直接給我方案**」或「**別這麼細**」,它會降檔簡化。
- 覺得逐點討論太慢:說「**一次列給我看**」,它會切換成清單模式。
- 它的任何推測都標成「提議」,你隨時可以**砍 / 改 / 駁回**;它猜錯你的意圖時,一句話就能扳回。
- 想要真正獨立的多專家平行審查(而非 AI 依序扮演):那需要 Claude Code 或 Cowork 的 subagent 環境。

## 一句提醒

這套流程是**刻意「慢而深」**的——它的價值在難題上,不在小事上。用對場合,它會幫你看見自己原本沒想到的面向。
