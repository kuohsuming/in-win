## 1. 簡介

### 1.1 目的

本文件定義表面平整檢查系統的需求，作為開發、測試與驗收的依據。每項需求皆有編號與驗收條件；系統須通過全部「必要」需求的驗收條件，方可上線。

### 1.2 範圍

本系統以 1 台 PC 讀取 3 台 KEYENCE DL-EN1 通訊單元、共 12 個接觸式探頭的測量值，逐點比對允收標準，在產線畫面上即時顯示合格或不合格，並將每片結果寫入 MySQL，可依日期匯出 Excel。

不在本版範圍：條碼／QR Code 掃描、統計報表、多工站同時連線、畫面上修改標準值、遠端重啟 DL-EN1。

### 1.3 名詞定義

| 名詞 | 定義 |
| --- | --- |
| 片 | 一次放置於治具上的待測表面，對應一個編號與一筆量測紀錄 |
| 量測點 | 12 個探頭之一，以「排＋位置」表示，例如「中排 右中」 |
| 排 | 前排、中排、後排；每排對應 1 台 DL-EN1、4 個探頭 |
| 允收標準 | 每個量測點的標準值、下限、上限 |
| 合格（PASS） | 12 點測量值全部介於下限與上限之間（含邊界） |
| 不合格（FAIL） | 至少 1 點超出上限（偏高）或低於下限（偏低） |
| 設備異常 | DL-EN1 無法連線，或任一探頭無法提供有效測量值；畫面以 FAIL 呈現，資料庫記為 ERROR |
| 重讀 | 對同一片重新倒數並讀取，編號不變 |
| 偵測 | 檢查 3 台 DL-EN1 與 12 個探頭是否可正常讀取 |

### 1.4 參考文件

| 文件 | 說明 |
| --- | --- |
| 表面平整檢查系統 功能規格 | 作業情境、畫面、資料表與異常代碼的詳細說明 |
| KEYENCE DL-EN1 通信單元使用手冊 | TCP 命令格式、錯誤代碼、ID00 資料編號 |
| KEYENCE GT2 系列使用手冊 | 放大器設定、預設（Preset）與錯誤處理 |

## 2. 整體描述

### 2.1 使用者

| 角色 | 使用的功能 | 特性 |
| --- | --- | --- |
| 作業員 | 下一片、重讀、查看結果 | 站立操作、距螢幕 1～2 公尺、不需專業知識 |
| 工程人員 | 偵測設備、排除設備異常、維護設定檔 | 熟悉 DL-EN1 與探頭 |
| 班長／品保 | 取出測試數據 | 依日期取得 Excel 紀錄 |

### 2.2 運作環境

| 項目 | 規格 |
| --- | --- |
| 量測 PC | Ubuntu Desktop 24.04 LTS；兩張網卡，設備網路與公司網路分開 |
| 顯示器 | 1 台，建議 24 吋以上、1920×1080 |
| 通訊單元 | KEYENCE DL-EN1 × 3，固定 IP，TCP 埠 64000 |
| 探頭 | GT2 系列放大器與探頭 × 12，每台 DL-EN1 串接 4 台 |
| 資料庫 | MySQL 8.4 LTS，安裝於量測 PC 本機，只接受本機連線 |
| 網路 | 設備網路不需連外；畫面須在離線狀態正常顯示 |

### 2.3 限制

- 每台 DL-EN1 同一時間只接受 1 條 TCP 連線，系統須以單一常駐連線完成偵測與量測。
- DL-EN1 無遠端重啟命令，也無網路自動探索功能；IP 與排的對應以設定檔為準。
- 不得透過程式執行放大器的「重置初始化」（GT2 資料編號 005），以免清除放大器設定。

### 2.4 假設與相依

- 探頭已依現場需求完成預設（Preset）校正，讀值為絕對高度（mm）。
- 量測 PC 時間已與網路時間同步（NTP），編號與匯出日期依此時間。
- 允收標準由品保提供，系統上線前更新至設定檔。

## 3. 功能需求

優先級：「必要」為上線前必須完成；「建議」可於後續版本補上。

### 3.0 安裝部署（INS）

第一個開發項目是**安裝包（install package）**：桌上型電腦安裝好 Ubuntu Desktop 24.04 後，只要執行安裝包，就能完成整台機器的安裝與設定，包含開放原始碼元件、MySQL 資料庫與資料表、BOOTP 服務、系統設定與 Python App，不需其他手動步驟。安裝包以單一壓縮檔交付（例：`flatness-installer-1.0.0.tar.gz`），可由隨身碟或網路取得，解壓後執行其中的 `install.sh`。

| 編號 | 需求 | 優先級 | 驗收條件 |
| --- | --- | --- | --- |
| INS-01 | 開發安裝包：在已安裝 Ubuntu Desktop 24.04 的桌上型電腦上，執行安裝包即完成整台機器的安裝與設定；安裝包進入點為 `install.sh`，以 `sudo ./install.sh` 執行 | 必要 | 全新安裝 Ubuntu 的測試機只執行安裝包、無其他手動步驟，重新開機後直接進入量測畫面，且安裝後檢查全部通過 |
| INS-02 | 現場參數（工站代號、設備網卡、DL-EN1 定義檔路徑、資料庫、時區與 NTP、掃碼器 USB ID）集中於 `site.conf`，安裝包內的程式本身不需修改 | 必要 | 僅修改 `site.conf` 即可安裝第二個工站 |
| INS-03 | 安裝系統套件：Python 3.12 虛擬環境、繁體中文字型、dnsmasq、維護工具 | 必要 | 套件皆已安裝 |
| INS-04 | 設定設備網卡固定 IP；安裝 dnsmasq 並產生只在設備網卡上運作的 BOOTP 主設定；停用並遮蔽作業系統的 `dnsmasq.service`，BOOTP 服務改由 App 啟動與管理（DSC-07） | 必要 | 重新開機後 `dnsmasq.service` 為 masked；App 啟動後 DL-EN1 上電即取得設定的 IP；公司網路上無 BOOTP 回應 |
| INS-05 | 安裝 MySQL 8.4 LTS，建立資料庫、App 專用帳號（僅 SELECT、INSERT、UPDATE 權限）與三張資料表（`inspection`、`inspection_point`、`lan_device`）；密碼自動產生並以權限保護存放 | 必要 | App 帳號可寫入、無法刪除資料表 |
| INS-06 | 建立 Python 虛擬環境並依 `requirements.txt` 安裝鎖定版本的套件；支援以 `wheels/` 目錄離線安裝 | 必要 | 斷網狀態下可完成安裝 |
| INS-07 | 部署 App 至 `/opt/flatness`，建立設定檔、日誌、暫存與 BOOTP 目錄，並設定開機自動登入、自動啟動 App、關閉螢幕鎖定 | 必要 | 重新開機後直接進入量測畫面 |
| INS-08 | 設定時區與 NTP 校時；設定掃碼器 udev 規則與權限 | 必要 | 時間同步啟用；掃碼器固定為 `/dev/barcode` |
| INS-09 | 可重複執行：已完成的步驟不重複安裝，現場已調整的設定檔與資料不被覆蓋 | 必要 | 連續執行兩次，資料與設定不變 |
| INS-10 | 安裝結束自動檢查並輸出報告；`--check` 可單獨執行檢查；完整紀錄寫入 `/var/log/flatness-install.log` | 必要 | 報告逐項顯示通過或未通過 |
| INS-11 | 安裝的開放原始碼元件與版本依 3.0.5 鎖定；升級任何元件前，須先於測試機驗證並更新 3.0.5 的版本表 | 必要 | 安裝完成後，實際安裝版本與 3.0.5 一致 |

#### 3.0.1 執行條件與方式

- 目標電腦已完成 Ubuntu Desktop 24.04 LTS 安裝，並建立執行 App 的桌面帳號。
- 以該帳號執行 `sudo ./install.sh` 完成安裝；`sudo ./install.sh --check` 只執行安裝後檢查。
- 安裝包須先檢查：以 root 權限執行、作業系統為 Ubuntu 24.04、`site.conf` 存在且欄位格式正確、設備網卡存在；任一不符即停止並顯示原因。
- 安裝完成後提示重新開機。

#### 3.0.2 安裝包內容

| 檔案或目錄 | 說明 |
| --- | --- |
| `install.sh` | 安裝包進入點，依序執行所有安裝步驟 |
| `site.conf` | 現場參數，每個工站唯一需要修改的檔案 |
| `requirements.txt` | Python 套件與鎖定版本 |
| `sql/schema.sql` | 資料表定義，只在資料表不存在時建立 |
| `app/` | 開發完成的 Python App |
| `files/fonts/` | 隨附字型（選用） |
| `wheels/` | 離線安裝用的 Python 套件（選用）；存在時改用離線安裝 |

#### 3.0.3 現場參數（site.conf）

| 參數 | 說明 | 範例 |
| --- | --- | --- |
| `STATION_ID` | 工站代號，寫入量測紀錄 | ST01 |
| `APP_USER` | 執行 App 的帳號；留空表示執行 sudo 的帳號 | （空白） |
| `AUTOLOGIN` | 開機是否自動登入 | yes |
| `EQUIP_IF` | 接 DL-EN1 的設備網卡名稱 | enp3s0 |
| `PC_IP`、`NET_PREFIX` | 設備網卡固定 IP 與網路遮罩長度 | 192.168.10.1、24 |
| `DLEN1_DEF_FILE` | 初始 DL-EN1 清單（格式見 3.7）；安裝時資料庫若沒有任何 DL-EN1，即以此檔匯入（DEF-10）。之後 DL-EN1 設定以資料庫為準，於 App「設備設定」維護 | dl-en1.json |
| `DB_NAME`、`DB_USER`、`DB_PASS` | 資料庫名稱、App 帳號、密碼；密碼留空則自動產生 | flatness、flatness\_app |
| `TIMEZONE`、`NTP_SERVERS` | 時區與校時伺服器 | Asia/Taipei、time.stdtime.gov.tw |
| `BARCODE_VID`、`BARCODE_PID` | 掃碼器 USB 廠商與產品 ID；尚未使用可留空 | （空白） |

#### 3.0.4 安裝與設定項目

安裝包依下列順序執行，每一步完成後顯示結果。

| 步驟 | 內容 | 產生或修改的檔案 |
| --- | --- | --- |
| 1. 系統套件 | 安裝 python3-venv、python3-pip、fonts-noto-cjk、dnsmasq、ufw、netcat-openbsd、tcpdump、curl、gnupg、rsync，以及 PySide6 所需的 libxcb-cursor0 等函式庫 | － |
| 2. 設備網卡 | 設定固定 IP，不使用 DHCP | `/etc/netplan/60-flatness-equipment.yaml` |
| 3. BOOTP 服務 | 安裝 dnsmasq，停用並遮蔽（mask）作業系統的 `dnsmasq.service`；產生 root 擁有、App 不可寫的主設定：只在設備網卡上運作、關閉 DNS、只配發主機對應中的 MAC、`log-dhcp`；防火牆在設備網卡開放 UDP 67；sudoers 只允許 App 帳號以固定參數執行 dnsmasq（僅此一項 root 權限）；主機對應檔由 App 產生（DSC-06） | `/etc/flatness/dnsmasq.conf`、`/var/lib/flatness/bootp/`、`/etc/sudoers.d/flatness` |
| 4. MySQL | 安裝 MySQL 8.4 LTS（官方 APT 套件庫），只接受本機連線；建立資料庫、App 帳號與資料表；資料庫沒有任何 DL-EN1 時，以 `DLEN1_DEF_FILE` 匯入 `lan_device`（DEF-10） | `/etc/mysql/conf.d/flatness.cnf`、`/etc/flatness/db.env` |
| 5. 時間 | 設定時區、啟用 NTP 校時 | `/etc/systemd/timesyncd.conf.d/flatness.conf` |
| 6. 掃碼器 | App 帳號加入 dialout 群組；設定 udev 規則，將掃碼器固定為 `/dev/barcode` 並排除 ModemManager 探測 | `/etc/udev/rules.d/99-flatness-barcode.rules` |
| 7. Python App | 建立虛擬環境、安裝鎖定版本套件、部署 App、建立 App 設定檔與目錄 | `/opt/flatness/venv`、`/opt/flatness/app`、`/etc/flatness/config.toml` |
| 8. 產線桌面 | 開機自動登入、自動啟動 App；關閉螢幕保護、自動鎖定與閒置休眠；自動安全更新後不自動重開機 | `~/.config/autostart/flatness.desktop`、`/etc/dconf/db/local.d/00-flatness`、`/etc/gdm3/custom.conf`、`/etc/apt/apt.conf.d/52flatness-no-reboot` |
| 9. 安裝後檢查 | 依 3.0.7 逐項檢查並輸出報告 | `/var/log/flatness-install.log` |

### 3.7 DL-EN1 定義檔（DEF）

DL-EN1 定義檔描述系統中有幾台 DL-EN1、每台的名稱、MAC 位址、指定的 IPv4 位址、最多可接幾個探頭，以及目前安裝了哪些探頭。DL-EN1 設定的**主檔為資料庫 `lan_device`（3.10）**；定義檔是 App 依資料庫產生的副本（DSC-06），也是匯入、匯出與備份所用的格式。由資料庫產生的設定用於以下三件事，其他設定檔不得重複定義 MAC 或 IP：

1. 轉換為 BOOTP 主機對應檔，由 dnsmasq 依 MAC 配發 IP。
2. App 連線的 DL-EN1 對象與讀值對應。
3. 畫面上每一排的名稱與每個探頭的位置名稱。

定義檔存放於 `/etc/flatness/dl-en1.json`（手動修改會在 App 下次啟動時被資料庫內容覆寫），格式為 JSON（UTF-8），欄位以 JSON Schema 正式定義（見 3.7.1）。

#### 3.7.1 欄位定義

| 層級 | 欄位 | 型別 | 必填 | 說明 | 限制 |
| --- | --- | --- | --- | --- | --- |
| 檔案 | `version` | 整數 | 是 | 定義檔格式版本 | 目前為 1 |
| 檔案 | `dl_en1` | 陣列 | 是 | DL-EN1 清單，畫面依此順序由上而下排列 | 1～8 台 |
| DL-EN1 | `key` | 字串 | 是 | 英數識別碼，用於 BOOTP 主機名稱與量測紀錄 | 小寫英文、數字、連字號，1～30 字，不可重複 |
| DL-EN1 | `name` | 字串 | 是 | 畫面顯示的排名稱，例：前排 | 1～10 字，不可重複 |
| DL-EN1 | `mac` | 字串 | 是 | DL-EN1 本體上的 MAC 位址 | `XX:XX:XX:XX:XX:XX`，不可重複 |
| DL-EN1 | `ipv4` | 字串 | 是 | 指定的 IPv4 位址 | 在設備網段內、非網路或廣播位址、不同於量測 PC，不可重複 |
| DL-EN1 | `port` | 整數 | 否 | DL-EN1 的 TCP 埠號。未填寫時使用預設值 64000（DL-EN1 出廠預設）。模擬模式下也作為該台模擬 DL-EN1 的埠號 | 1～65535，預設 64000 |
| DL-EN1 | `max_probes` | 整數 | 是 | 這台 DL-EN1 最多可接的探頭數 | 1～15（DL-EN1 最多串接 15 台放大器） |
| DL-EN1 | `probes` | 陣列 | 是 | 目前已安裝的探頭，畫面依 `id` 由左至右排列 | 1 個以上，不超過 `max_probes` |
| 探頭 | `id` | 整數 | 是 | 探頭編號，等於放大器 ID，依實體串接順序由 1 起算 | 1～`max_probes`，同一台內不可重複 |
| 探頭 | `description` | 字串 | 是 | 畫面顯示的位置名稱，例：左、左中 | 1～10 字 |

DL-EN1 數量為 1～8 台；畫面依檔案中的順序由上而下排列，探頭依 `id` 由左至右排列。

**JSON Schema**（JSON Schema 2020-12，App 驗證上傳檔案與測試驗收的正式依據）：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "DL-EN1 定義檔",
  "type": "object",
  "required": ["version", "dl_en1"],
  "additionalProperties": false,
  "properties": {
    "version": { "const": 1 },
    "dl_en1": {
      "type": "array",
      "minItems": 1,
      "maxItems": 8,
      "items": { "$ref": "#/$defs/device" }
    }
  },
  "$defs": {
    "device": {
      "type": "object",
      "required": ["key", "name", "mac", "ipv4", "max_probes", "probes"],
      "additionalProperties": false,
      "properties": {
        "key":        { "type": "string", "pattern": "^[a-z0-9][a-z0-9-]{0,29}$" },
        "name":       { "type": "string", "minLength": 1, "maxLength": 10 },
        "mac":        { "type": "string", "pattern": "^([0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2}$" },
        "ipv4":       { "type": "string", "format": "ipv4" },
        "port":       { "type": "integer", "minimum": 1, "maximum": 65535, "default": 64000 },
        "max_probes": { "type": "integer", "minimum": 1, "maximum": 15 },
        "probes": {
          "type": "array",
          "minItems": 1,
          "maxItems": 15,
          "items": { "$ref": "#/$defs/probe" }
        }
      }
    },
    "probe": {
      "type": "object",
      "required": ["id", "description"],
      "additionalProperties": false,
      "properties": {
        "id":          { "type": "integer", "minimum": 1, "maximum": 15 },
        "description": { "type": "string", "minLength": 1, "maxLength": 10 }
      }
    }
  }
}
```

驗證分兩階段：先以 JSON Schema 檢查結構、型別與格式（須啟用格式檢查，`ipv4` 才會被驗證）；再由 App 檢查 Schema 無法表達的跨欄位規則：`key`、`name`、`mac`、`ipv4` 在所有 DL-EN1 間不可重複；同一台內探頭 `id` 不可重複且不超過 `max_probes`；`probes` 數量不超過 `max_probes`；`ipv4` 須在設備網段內、不得為網路位址、廣播位址或量測 PC 的 IP。

#### 3.7.3 需求

| 編號 | 需求 | 優先級 | 驗收條件 |
| --- | --- | --- | --- |
| DEF-01 | 資料庫 `lan_device` 中「DL-EN1 使用中」的設備為 DL-EN1 連線對象、BOOTP 對應與畫面配置的唯一來源；App 啟動時依此產生定義檔（DSC-06）。資料庫無法連線時沿用現有定義檔 | 必要 | 只在「設備設定」修改即可改變 DL-EN1 數量、名稱與探頭配置；停止 MySQL 後 App 仍依現有定義檔啟動 |
| DEF-02 | 自資料庫讀出、匯入或在畫面編輯的 DL-EN1 設定，皆依 3.7.1 逐項驗證；有錯誤時不套用，畫面顯示錯誤的欄位與原因，並沿用上一版有效的定義檔 | 必要 | 以重複 MAC、網段外 IP、探頭 id 超過 max\_probes 等錯誤檔測試，皆被拒絕且說明正確 |
| DEF-03 | 由資料庫產生 BOOTP 主機對應檔（每台一行：MAC、IPv4、名稱；含 DL-EN1 使用中與設有 IP 的非 DL-EN1，MAC 與 IP 不可重複），先備份舊檔再覆寫，並由 App 以新對應重新啟動 dnsmasq（DSC-07）；重新啟動失敗時自動還原；備份保留最近 20 份 | 必要 | 修改 IP 後，對應 DL-EN1 重新上電即取得新 IP |
| DEF-04 | 畫面依定義檔產生：每台 DL-EN1 一排，排名稱為 `name`；每排只顯示已安裝的探頭，位置名稱為 `description` | 必要 | 新增或移除探頭後，畫面版面與定義檔一致 |
| DEF-05 | 讀值時，`MS` 回應中第 N 組資料對應放大器 ID N；只處理定義檔中已安裝的探頭，未定義的 ID 不顯示、不判定、不寫入 | 必要 | 實際接 4 台但只定義 2 個探頭時，只顯示與判定這 2 點 |
| DEF-06 | 偵測設備時比對 DL-EN1 實際連接台數（ID00 資料編號 077）：少於已安裝探頭的最大 id 時，缺少的探頭標示「探頭無回應」；多於 `max_probes` 時標示設備異常「探頭台數超出定義」 | 必要 | 拔除一台放大器，對應探頭顯示探頭無回應 |
| DEF-07 | 工程人員可在 App 畫面上傳定義檔匯入資料庫，流程與細節見 3.8 | 必要 | 匯入後資料庫、畫面與 BOOTP 對應立即更新，可從備份還原 |
| DEF-08 | 量測紀錄以 DL-EN1 `key` 加探頭 `id` 識別量測點，並保存當時的 `name` 與 `description`，避免定義檔變更後無法辨識舊紀錄 | 必要 | 修改探頭名稱後，舊紀錄仍顯示原名稱 |
| DEF-09 | 允收標準以 DL-EN1 `key` 加探頭 `id` 對應；已安裝但未設定允收標準的探頭，顯示設備異常「未設定允收標準」，不得判為合格 | 必要 | 新增探頭未設標準時，整片不出現合格 |
| DEF-10 | 安裝時資料庫若沒有任何 DL-EN1，以 `site.conf` 指定的定義檔匯入 `lan_device`（狀態為使用中）；已有資料則不變 | 必要 | 全新安裝後首次啟動 App，BOOTP 對應與安裝包定義檔一致；重複安裝不改變資料庫中的 DL-EN1 |

資料表配合調整：`inspection_point` 以 `device_key`、`probe_id` 取代原本的 `row_no`、`pos_no`，並增加 `device_name`、`probe_description` 欄位。

### 3.8 上傳 DL-EN1 定義檔（UPL）

Python App 須提供上傳 DL-EN1 定義檔的功能，讓工程人員不必登入作業系統、不必手動改檔，即可新增或更換 DL-EN1、調整探頭配置與名稱。上傳的檔案經驗證、預覽差異並確認後才匯入資料庫：檔案中的 DL-EN1 設為「使用中」，原本使用中但不在檔案內者設為「已停用」；再依 DSC-06 產生定義檔與 BOOTP 主機對應。套用失敗時資料庫與檔案皆還原，產線畫面維持原配置。

#### 3.8.1 操作流程

| 步驟 | 畫面與系統行為 |
| --- | --- |
| 1. 開啟 | 頂端工具列「設備設定」→「上傳定義檔」，輸入工程人員密碼 |
| 2. 選擇檔案 | 開啟系統檔案選擇視窗，可選擇隨身碟或本機上的 `.json` 檔 |
| 3. 驗證 | 依序檢查 JSON 語法、JSON Schema、跨欄位規則（見 3.7.1）；有錯誤時逐項列出並停止 |
| 4. 差異預覽 | 以新舊對照顯示新增、移除、變更的 DL-EN1 與探頭，並列出影響 |
| 5. 確認套用 | 使用者按「套用」後才寫入；按「取消」不做任何變更 |
| 6. 套用 | 備份目前設定 → 寫入資料庫 → 產生定義檔與 BOOTP 主機對應 → 重新啟動 dnsmasq → 重新載入畫面 → 自動執行偵測設備 |
| 7. 結果 | 顯示套用成功或失敗原因；IP 或 MAC 有變更時，列出需重新上電的 DL-EN1 |

#### 3.8.2 需求

| 編號 | 需求 | 優先級 | 驗收條件 |
| --- | --- | --- | --- |
| UPL-01 | 上傳、設備清單與分類（DSC）皆位於頂端工具列「設備設定」，需輸入工程人員密碼才能使用 | 必要 | 未輸入正確密碼無法進入設備設定 |
| UPL-02 | 只能在「待放置」或量測結果顯示時使用；倒數、讀取中、偵測中停用。畫面上若有尚未寫入的量測結果，開始上傳前先寫入資料庫 | 必要 | 倒數期間按鍵停用；上傳前的量測結果完整寫入資料庫 |
| UPL-03 | 以系統檔案選擇視窗選檔，可選擇隨身碟；只接受副檔名 `.json`、UTF-8 編碼、大小 64 KB 以內的檔案 | 必要 | 選擇其他副檔名或過大的檔案時顯示原因並拒絕 |
| UPL-04 | 依序驗證 JSON 語法、JSON Schema 與跨欄位規則；語法錯誤顯示行號與列號，其他錯誤顯示欄位位置（例：`dl_en1[1].probes[2].id`）與原因，並一次列出所有錯誤 | 必要 | 以含多個錯誤的檔案測試，所有錯誤皆列出且位置正確；檔案未被套用 |
| UPL-05 | 差異預覽：逐項列出新增、移除、變更的 DL-EN1 與探頭；MAC 或 IP 變更以醒目顏色標示；另列出影響：需重新上電的 DL-EN1、尚未設定允收標準的探頭、將從畫面移除的量測點 | 必要 | 預覽內容與兩份檔案的實際差異一致 |
| UPL-06 | 使用者確認後才套用；套用前備份目前的 DL-EN1 設定（定義檔格式）與 BOOTP 主機對應，備份檔名含時間，保留最近 20 份 | 必要 | 每次套用都產生一份備份；超過 20 份時刪除最舊的 |
| UPL-07 | 定義檔以原子方式覆寫（先寫暫存檔再改名），避免斷電造成檔案殘缺 | 必要 | 寫入過程中斷電，重開後定義檔為完整的新檔或舊檔 |
| UPL-08 | 套用後依序：寫入資料庫、產生定義檔與 BOOTP 主機對應、由 App 重新啟動 dnsmasq、重新載入畫面配置、自動執行偵測設備；任一步驟失敗即自動還原資料庫、定義檔與 BOOTP 主機對應，畫面維持原配置並顯示失敗原因 | 必要 | 模擬 dnsmasq 重新啟動失敗，資料庫與檔案皆還原為上傳前狀態 |
| UPL-09 | 套用成功後，若有 DL-EN1 的 MAC 或 IP 變更，顯示需重新上電的 DL-EN1 清單 | 必要 | 變更 IP 後畫面列出該 DL-EN1 |
| UPL-10 | 可從備份清單（顯示備份時間）選擇一份還原；還原即以該備份匯入資料庫，同樣經過差異預覽與確認 | 必要 | 還原後資料庫、定義檔、BOOTP 對應與畫面皆回到該備份的內容 |
| UPL-11 | 可下載目前使用中的定義檔（另存新檔），作為修改範本 | 建議 | 下載的檔案可直接再次上傳且驗證通過 |
| UPL-12 | 每次上傳、套用、還原都寫入日誌：時間、檔名、結果、差異摘要、失敗原因 | 必要 | 日誌可查到每次操作紀錄 |
| UPL-13 | 上傳定義檔不影響已寫入的量測紀錄；舊紀錄保留當時的 DL-EN1 與探頭名稱（見 DEF-08） | 必要 | 更改探頭名稱後，舊紀錄仍顯示原名稱 |

除了上傳檔案，工程人員也可在「設備設定」畫面直接維護 DL-EN1 清單，不必另外準備 JSON 檔。編輯結果與上傳的檔案走同一套驗證、預覽、套用與還原流程。

| 編號 | 需求 | 優先級 | 驗收條件 |
| --- | --- | --- | --- |
| EDT-01 | 「設備設定」畫面可新增、刪除、修改 DL-EN1（key、名稱、MAC、IPv4、埠、最多探頭數）與其探頭（ID、位置名稱），並可調整 DL-EN1 的排列順序 | 必要 | 不使用任何檔案，即可在畫面上完成新增一台、修改一台 IP、刪除一台並套用 |
| EDT-02 | 按「套用」前不寫入任何檔案；有尚未套用的變更時畫面顯示提示，關閉畫面前詢問是否放棄 | 必要 | 編輯後按關閉並選擇放棄，定義檔與 BOOTP 主機對應皆不變 |

### 3.9 DL-EN1 模擬器（SIM）

開發一支 DL-EN1 模擬器，在沒有實體 DL-EN1 與探頭的情況下，接受 Python App 的 TCP 連線，依收到的命令回應模擬的探頭測量值與設備狀態。用途是開發與測試：重現合格、不合格與各種設備異常，驗證 App 的畫面、判定與例外處理，並支援自動化測試。模擬器與 Python App 在同一台機器上執行：開發機上常態使用；產線 PC 上只在 DL-EN1 尚未到位或維修測試時暫時使用，不隨安裝包自動安裝，也不開機自動啟動。

#### 3.9.1 架構

| 項目 | 說明 |
| --- | --- |
| 執行環境 | Python 3.12，與 App 在同一台 Ubuntu 24.04 機器上執行 |
| 設備組成 | 讀取 App 使用的同一份 DL-EN1 定義檔（3.7），每台 DL-EN1 啟動一個 TCP 伺服器，探頭數量、編號與定義檔一致；定義檔中的 `mac`、`ipv4` 不使用 |
| 連線位址 | 模擬器**不支援 BOOTP**。啟動時自動取得本機（桌上型電腦）的 IPv4 位址並綁定；各台模擬 DL-EN1 共用此 IP，埠號取自定義檔各台的 \`port\`，未填寫則為 64000；若有重複埠號，重複者依定義檔順序自動往後遞增至未使用的埠號，並於啟動時顯示 |
| 本機 IP 的取得 | 預設取預設路由所在網卡的 IPv4；可用啟動參數 `--bind-ip` 指定。取得失敗時顯示原因並停止 |
| App 端 | App 以模擬模式啟動時，依相同規則取得本機 IP 與埠（見 3.9.4） |
| 情境檔 | JSON 格式，描述每個探頭的數值與時間軸上的事件（見 3.9.3） |
| 控制方式 | 啟動時指定情境檔；執行中可由命令列切換情境，不需重啟 |

#### 3.9.2 需求

| 編號 | 需求 | 優先級 | 驗收條件 |
| --- | --- | --- | --- |
| SIM-01 | 依 DL-EN1 定義檔啟動對應數量的模擬 DL-EN1，每台為一個獨立的 TCP 伺服器，可指定綁定位址與埠 | 必要 | 以 3 台定義檔啟動，App 可同時連上 3 台 |
| SIM-02 | 通訊格式與實機相同：ASCII、命令與回應以 CR LF 結尾、一問一答；支援 `M0`、`MS`、`SR`、`SW`、`FR` 命令，格式錯誤回應 `ER,**,255` | 必要 | 以 DL-EN1 手冊 2-4 節的格式逐一驗證 |
| SIM-03 | 支援 App 使用的資料編號：ID00 的 000、001、008、009、038～040、044～058、077、668～683；GT2 的 033、037、065、066。未支援的資料編號回應 `ER,SR,020` | 必要 | 每個資料編號皆回應正確格式 |
| SIM-04 | 測量值以「基準值 ＋ 雜訊」產生，基準值與雜訊幅度可依探頭設定；可設定放置後的穩定時間，期間數值逐漸收斂，用來驗證 App 的等待秒數是否足夠 | 必要 | 穩定時間內讀值變動大於穩定後 |
| SIM-05 | 依各探頭的 HIGH／LOW 設定值回傳輸出狀態（GO、HIGH、LOW），與測量值一致 | 必要 | 測量值超過上限時輸出狀態為 01 |
| SIM-06 | 同一時間只接受 1 條 TCP 連線；第 2 條連線的處理方式可設定為「立即拒絕」或「接受但不回應」，以重現實機可能的行為 | 必要 | 兩種設定下，App 皆能正確判斷並重試 |
| SIM-07 | 可模擬下列情境，每個探頭或每台 DL-EN1 可個別設定 | 必要 | App 對每種情境的畫面與判定符合功能規格 |
| SIM-08 | 情境可在時間軸上排程，例如「前 10 秒啟動中，第 30 秒中排斷線，第 60 秒恢復」，供自動化測試重現同樣的過程 | 必要 | 同一情境檔執行兩次，事件發生時間一致 |
| SIM-09 | 可設定亂數種子，使雜訊數值可重現；提供 pytest fixture，可在測試中啟動、切換情境與停止模擬器 | 必要 | 相同種子產生相同數值序列 |
| SIM-10 | 記錄每筆收到的命令與送出的回應（含時間與連線來源）至日誌與畫面 | 必要 | 日誌可對照 App 送出的每一個命令 |
| SIM-11 | 執行中可由命令列切換情境、調整單一探頭數值、讓指定 DL-EN1 斷線或恢復，不需重啟 | 建議 | 切換後下一次讀取即反映新狀態 |

**SIM-07 須支援的情境**

| 分類 | 情境 | 模擬方式 |
| --- | --- | --- |
| 量測結果 | 合格 | 所有測量值在允收範圍內，輸出狀態 04 |
| 量測結果 | 偏高、偏低 | 指定探頭的測量值超出上限或低於下限，輸出狀態 01 或 02 |
| 探頭異常 | 特殊值 | 回傳 `+100000000`、`+099999999`、`-099999999`、`-099999998` |
| 探頭異常 | 放大器錯誤 | 輸出狀態 03，並可由 `SR,00,668`～`683` 與 GT2 資料編號 033 讀到指定的錯誤代碼（例：02H 感測頭錯誤） |
| 探頭異常 | 探頭缺少 | 實際連接台數（077 與 `MS` 欄位數）少於定義 |

| 設備異常 | DL-EN1 無回應 | 不接受連線，或接受連線但不回應 |
| 設備異常 | 連線中斷 | 量測中主動斷開 TCP 連線 |
| 設備異常 | 啟動中 | 指定秒數內對所有命令回應 `ER,**,031` 或 `ER,**,254` |
| 設備異常 | 本機錯誤 | `SR,00,000` 回報錯誤位元，`SR,00,009` 回傳指定錯誤代碼（例：51、57、70） |

| 通訊異常 | 格式錯誤 | 回傳欄位數不符或缺少 CR LF 的回應 |

#### 3.9.4 與 App 同機執行

模擬器與 App 在同一台機器上，模擬器不支援 BOOTP，啟動時直接取得桌上型電腦的 IP；App 須提供「模擬模式」改連這個 IP 上的模擬 DL-EN1，並確保模擬資料不會與正式量測紀錄混在一起。

```
同一台桌上型電腦（例：本機 IP 192.168.1.50）
┌────────────────────────┐        ┌───────────────────────────────────┐
│ Python App（模擬模式）  │  TCP   │ DL-EN1 模擬器（不支援 BOOTP）       │
│ 讀 dl-en1.json          │ ─────▶ │ 192.168.1.50:64000  前排           │
│ 連線改用本機 IP 與埠     │ ─────▶ │ 192.168.1.50:64001  中排           │
│                        │ ─────▶ │ 192.168.1.50:64002  後排           │
└────────────────────────┘        └───────────────────────────────────┘
            │ 寫入                          ▲ 讀取同一份 dl-en1.json
            ▼                               │ 與情境檔
   測試資料庫 flatness_sim
```

**連帶修訂的既有需求（2026-10-06 已同步修訂於各節）**

- **DEF-01**：DL-EN1 設定的唯一來源改為資料庫 `lan_device`；`dl-en1.json` 改為由 App 依 DSC-06 產生的副本，供資料庫無法連線時沿用及模擬器（SIM）讀取；手動修改該檔會在下次啟動時被覆寫。
- **DEF-02**：驗證規則不變，改為套用於資料庫讀出的資料。
- **DEF-03**：BOOTP 主機對應由資料庫產生（DL-EN1 使用中 ＋ 設有 IP 的非 DL-EN1），MAC 與 IP 不可重複。
- **DEF-07／UPL**：上傳定義檔改為「匯入資料庫」：驗證、預覽、確認後寫入資料庫（檔案中的 DL-EN1 設為使用中，原本使用中但不在檔案內者設為已停用），再依 DSC-06 產生檔案。
- **DEF-10**：安裝時資料庫若沒有任何 DL-EN1，以安裝包的 `dl-en1.json` 匯入；已有資料則不變。
- **UPL-01**：設備清單與分類位於「設備設定」，同受工程人員密碼保護。
- **INS-04／3.0.4 步驟 3**：安裝包停用並遮蔽（mask）作業系統的 `dnsmasq.service`；產生 root 擁有、App 不可寫的主設定 `/etc/flatness/dnsmasq.conf`（設備網卡、只做 BOOTP/DHCP、`log-dhcp`、主機對應檔路徑）；sudoers 只允許 App 帳號以固定參數執行 dnsmasq（取代原本的 `systemctl restart dnsmasq`）。
- **3.0.7 安裝後檢查**：「BOOTP 服務：dnsmasq 運作中」改為「`dnsmasq.service` 已遮蔽、主設定檢查（`dnsmasq --test`）通過」；dnsmasq 運作與否改由 App 啟動後確認。
- **DEF-03／UPL-08**：「重啟 dnsmasq」改為由 App 以新主機對應重新啟動其 dnsmasq；重新啟動失敗時還原，與現行規則相同。
- **sql/in-win.sql**：新增 `lan_device` 資料表。

**設計備註（非需求）**：IP 佔用探測（DSC-10）以一般權限的 ping 觸發 ARP 解析，再讀取作業系統鄰居表（`ip neigh show <IP> dev <設備網卡>`）取得回應者 MAC；不需擷取封包的權限，設備即使不回應 ping 仍會回應 ARP。App 以子程序方式執行 dnsmasq（`sudo -n /usr/sbin/dnsmasq --keep-in-foreground --log-facility=- --conf-file=/etc/flatness/dnsmasq.conf`，sudoers 只允許此完整命令），dnsmasq 綁定埠後自行降為 `dnsmasq` 帳號執行。探索執行緒直接讀取 dnsmasq 的輸出（`log-dhcp` 會記錄每一筆 BOOTP／DHCP 請求，包含未登錄的 MAC、主機名稱與廠商識別），不需擷取封包的權限，也不需讀取系統日誌。dnsmasq 未執行時不會探索，此時任何設備也無法取得 IP。日誌格式須以實機 DL-EN1 驗證。資料庫 → 檔案的產生程序（DSC-06）只有一套，App 啟動與設備設定套用共用；寫檔沿用原子覆寫、備份與 dnsmasq 重啟失敗還原（UPL-06～UPL-08）。
