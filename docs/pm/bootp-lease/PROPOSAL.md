# 提案：BOOTP 拒絕配發的修復與提示

> 表面平整檢查系統的設備網路修正。三件事：
> - BOOTP 服務（dnsmasq）不再保存租約，IP 只依 App 產生的主機對應配發。
> - 設定 IP 時，不論佔用者是否在線都提出告警。
> - BOOTP 拒絕配發時，畫面寫出原因與處理方式。
>
> 對應需求：需求規格書 3.10 DSC-21～DSC-23（待確認）。修訂條文見第 4 節。
> 狀態：rev 2（spectra-review 第 1 輪修正），待 PO 逐條簽核。

## 1. 事件（2026-11-02，mosa）

依 `.dev/flatness.log` 整理：

| 時間 | 經過 | dnsmasq 日誌 |
| --- | --- | --- |
| 09:40 | 工程人員在設備設定刪除舊設備（前沿、試用等） | — |
| 09:41～10:20 | 新平台的 DL-EN1 plat1（`74:95:A7:15:9B:82`）上電，每 3～5 秒送一次 BOOTP。它在清單中仍是「不明」，設定**尚未儲存**，主機對應沒有它。期間工程人員 4 次按「探頭偵測」，都逾時 | `no address available` × 545 |
| 10:20:37 | 儲存：plat1 設為使用中、IP 192.168.10.11。主機對應改變，App 重新啟動 dnsmasq | — |
| 10:20～10:42 | dnsmasq 拒絕：192.168.10.11 在租約檔中登記給另一個 MAC，期限永久。主畫面每 13 秒顯示「偵測不到（timed out）」 | `192.168.10.11 … address in use` × 304 |
| 10:41 | PO 以 sudo 刪除租約檔中 `00:01:fc:de:3a:75` 的兩行 | — |
| 10:42:18 | 重新啟動 App，dnsmasq 重讀租約檔；1 秒後 plat1 取得 .11，偵測到 12 支探頭 | 配發成功（行尾無拒絕字串） |

佔用 .11 的舊租約登記在 `00:01:fc:de:3a:75`（舊的第 1 台「前沿」）。依據：10-07 DSC-20 測試時，前排由 .11 改為 .21，租約檔中兩筆都還在。

### 1.1 兩個原因

| 原因 | 時長 | 根本問題 |
| --- | --- | --- |
| A. 設定尚未儲存 | 39 分 | 畫面上的「使用中」與 IP 要按「儲存」才寫入主機對應。儲存前按「探頭偵測」只看到逾時，看不出是因為還沒儲存 |
| B. 舊租約佔用 IP | 22 分 | ① 租約檔與主機對應是兩份資料：App 只管主機對應，刪除設備、改 IP 都不會動到租約檔<br>② 租約永久有效（`dhcp-range … infinite`），dnsmasq 每次啟動都重讀，「重新啟動 dnsmasq」清不掉<br>③ 租約檔由 root 擁有，工程人員在畫面上無法處理<br>④ 畫面只顯示逾時，沒有原因 |

### 1.2 什麼情況會再發生

- 原因 A：每次新增設備都可能發生，只要在儲存前就去偵測。
- 原因 B：一個 IP 從 A 設備改給 B 設備，而 A 曾經向這台電腦取得過它。例如換新機（刪除舊機後設定新機）、兩台對調 IP、已停用設備的 IP 給新機（DSC-09）。替換（DSC-14）會在同一次儲存中把 IP 交給新機，同樣會發生。

## 2. PO 提議與評估（2026-11-02）

| 提議 | 現況 | 本提案 |
| --- | --- | --- |
| 核對設定檔的 IP 與 MAC | 主機對應依資料庫產生，當天內容正確 | 問題在租約檔，DSC-21 讓 dnsmasq 不再使用它 |
| IP 被佔用就告警，不論在線與否 | 資料庫中使用中、維修中、其他設備的 IP 重複時禁止儲存（DSC-08）；在線設備以 ARP 探測警告（DSC-10） | DSC-22 補上不在線的佔用者：曾經使用此 IP 的其他設備，以及舊租約 |

## 3. 設計

### 3.1 DSC-21：dnsmasq 不保存租約

1. **主設定**：安裝包產生的 `/etc/flatness/dnsmasq.conf` 加入 `leasefile-ro`，dnsmasq 不讀、不寫租約檔。
   - mosa 的 dnsmasq 2.90 以 `--test` 確認語法正確；實際行為以 AC-5 驗證。
2. **IP 只依主機對應配發**：同一 MAC 永遠得到主機對應中的 IP。
   - 主機對應改變時，App 依 DSC-07 停止並重新啟動 dnsmasq，記憶體中的租約一併清除。
   - 同一次儲存中兩台對調 IP，主機對應也會改變，同樣會重新啟動。
3. **主設定有變更時，安裝包立即讓新設定生效**：`03-bootp.sh` 在主設定寫入後執行停止程式 `flatness-stop-dnsmasq`。
   - App 的 dnsmasq 監控把它當成異常結束，約 2 秒後以新主設定重新啟動，不需要新增 sudo 權限。
   - 這段期間主畫面短暫顯示「BOOTP 服務停止」，日誌有紀錄。
   - App 沒在執行時，停止程式找不到程序，不影響安裝。
4. **舊租約檔改名保存**：加入 `leasefile-ro` 時，把 `/var/lib/misc/dnsmasq.leases` 改名為 `dnsmasq.leases.flatness-old`，並記入安裝日誌。
   - 避免日後設定被改回（例如重跑舊版安裝包）時，舊的永久租約整批復活。
5. **不影響**：
   - 設備探索（DSC-01）：讀 dnsmasq 日誌。
   - 實際使用 IP（DSC-19）：讀 ARP。
   - DL-EN1 本身記住 IP：改 IP 仍要按 RST。
6. **現有機器的升級**：
   - 由維護人員執行一次 `sudo ./installer/setup-bootp.sh`。
   - 它會重寫 BOOTP 相關設定（設備網卡、主設定、停止程式、ARP 監聽程式、sudoers、防火牆），內容相同的不變，可重複執行。
   - App 不必關閉，第 3 點會讓新設定立即生效。
   - 先更新 App 或先跑安裝包都可以；兩者都完成前，DSC-22 ② 會提示尚未升級。
7. **安裝後檢查（3.0.7）**：在 `03-bootp.sh` 的 `dnsmasq --test` 之後，確認主設定含 `leasefile-ro`，否則中止並說明。

### 3.2 DSC-22：IP 佔用告警（不論是否在線）

設定或變更 IP 時，在 DSC-08（資料表衝突，禁止）與 DSC-10（ARP 探測在線設備，警告）之外，另外檢查兩種不在線的佔用者：

**① 曾經使用此 IP 的其他設備**（資料表 `lan_device.seen_ip`）
- 條件：MAC 不是本機，且 `seen_ip` 等於此 IP。
- 排除：
  - DSC-08 已報錯的設備（會配發 IP 且 `ipv4` 等於此 IP）。
  - 本次編輯中被替換的舊機：沿用 DSC-14 的舊機提示，改為不論是否在線都顯示「舊機仍記得此 IP，請勿再接上網路」。
- 同一 MAC 已由 DSC-10 回報（在線）時，合併成一條，以 DSC-10 為準。
- 訊息例：「00:01:FC:DE:3A:70（已停用 舊機）最後於 10/07 13:51 使用 192.168.10.12；它仍記得這個 IP，接上網路會衝突」。
- `seen_ip` 只由 ARP 更新、不會清除，所以列出最後出現日期，讓工程人員自行判斷是否還在現場。
- 已從清單**刪除**的設備沒有資料列，無法檢查（第 7 節）。

**② 舊租約**
- 條件（任一成立就檢查）：
  - 主設定沒有 `leasefile-ro`；或
  - 執行中的 dnsmasq 啟動時間早於主設定的修改時間（升級後還沒重新啟動）。
- 檢查方式：讀 `/var/lib/misc/dnsmasq.leases`，此 IP 登記給其他 MAC 時警告。
- 訊息：「192.168.10.11 仍被舊租約登記給 00:01:FC:DE:3A:75，BOOTP 會拒絕配發；請維護人員執行 sudo ./installer/setup-bootp.sh」。
- 主設定與租約檔都是 644，App 可讀；App 不寫入。dnsmasq 的啟動時間取自 `/proc/<pid>/stat`，dnsmasq.py 已讀過 `/proc`。

兩種都是**警告**：列在檢查訊息與確認儲存頁，不阻擋儲存（與 DSC-10 相同；佔用者可能已不存在）。

### 3.3 DSC-23：BOOTP 拒絕配發時寫出原因

**判定**（App 已逐行讀 dnsmasq 日誌，DSC-01）

只看「DL-EN1 使用中」與「維修中」設備的 BOOTP／DHCP 請求行：

| 行尾 | 意思 | 狀態 |
| --- | --- | --- |
| `address in use` | 主機對應有這台，但 IP 被其他 MAC 的租約佔用 | 拒絕：佔用 |
| `no address available`、`no address configured` | 主機對應沒有這台：設定尚未儲存，或 IP 不在設備網段 | 拒絕：未配發 |
| `wrong network`、`ignored`、`disabled` | 其他原因 | 拒絕：其他（顯示原字串） |
| 有 IP，行尾沒有上述字串 | 已配發 | 恢復 |

另外，**最近一次被拒之後**收到的 ARP 封包顯示實際使用 IP 等於設定 IP（DSC-19），也視為恢復。不能只看資料表中的 `seen_ip`：它可能是被拒之前留下的舊值。

**狀態**
- 由 backend 保存每個 MAC 的狀態：原因、IP、第一次與最近一次被拒的時間。狀態改變時以 Signal 通知主畫面與設定頁；設定頁之後才開啟也讀得到。
- App 重新啟動後狀態歸零，再被拒時重新判定。

**主畫面**

| 情況 | 方塊 | 頂端提示（新類型，顏色同設備異常） |
| --- | --- | --- |
| 使用中、拒絕：佔用 | 「拿不到 IP」，取代「偵測不到」 | 「第 N 台 名稱 拿不到 IP：<IP> 被其他設備佔用（BOOTP 拒絕配發），請洽維護人員」 |
| 使用中、拒絕：未配發 | 同上 | 「第 N 台 名稱 拿不到 IP：BOOTP 沒有配發（設定尚未儲存，或 IP 不在設備網段）」 |
| 維修中、任一拒絕 | 「拿不到 IP・維修中」，不進入異常橫幅（DSC-15 不阻擋作業） | 同上 |

- 被拒期間，該台的「IP 不符」（DSC-20）標示與「請按 RST」提示暫停。原因：按 RST 後設備放棄舊 IP 再要 IP，卻被拒；這時 `seen_ip` 仍是舊 IP，若照 DSC-20 會繼續叫人按 RST，與 DSC-23 互相矛盾。
- 恢復後提示自動消失，DSC-20 照常判斷。

**設定頁**
- 該台資訊列：「BOOTP：拒絕配發（address in use），最近 10:30:24」。
- 「探頭偵測」失敗時：
  - 這台的狀態或 IP 尚未儲存：提示「設定尚未儲存，BOOTP 還沒有配發 <IP>；請先儲存」。
  - 這台正被拒絕：提示拒絕原因。

**日誌**
- App 的 WARNING 只在狀態改變時各記一筆：第一次被拒、原因改變、恢復。
- dnsmasq 的原始輸出照常寫入日誌（DSC-01 探索需要）。

## 6. 實作順序

1. M1 安裝包：`leasefile-ro`、租約檔改名、停止程式、安裝後檢查。
2. M2 日誌判定與 backend 狀態（DSC-23）。
3. M3 主畫面與設定頁的顯示（DSC-23、PDT-01 修訂）。
4. M4 設定頁的佔用告警（DSC-22）。
5. M5 文件、截圖、變更紀錄。
6. M6 真機確認（mosa）。先不跑安裝包，造一筆舊租約驗證 AC-2；再在 App 執行中跑 `setup-bootp.sh` 驗證 AC-3。AC-3 不可用對調 IP 代替，對調會改變主機對應、本來就會重新啟動。

## 7. 風險與未納入

| 項目 | 處理 |
| --- | --- |
| 安裝包停止 dnsmasq 後，約 2 秒沒有 BOOTP 服務 | 正在要 IP 的設備會重送，幾秒內取得；畫面短暫顯示「BOOTP 服務停止」 |
| 舊的 DL-EN1 仍記住 IP，接回網路造成真實 IP 衝突 | 仍在清單中時由 DSC-22 ① 警告；在線時 DSC-10 也會發現。App 無法改掉 DL-EN1 記住的 IP |
| 候選（未納入）：刪除持有 IP 的 DL-EN1 時提示「它仍記住 IP x」 | 刪除後資料列消失，DSC-22 ① 無法再警告。本次事件的前沿就是這樣：被刪除，DSC-22 ① 抓不到，只有 ② 抓得到。若 PO 需要，另立條目 |
