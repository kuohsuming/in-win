# 提案：BOOTP 舊租約佔用 IP 的修復

> 表面平整檢查系統的設備網路修正。BOOTP 服務（dnsmasq）不再保存租約，IP 只依 App 產生的主機對應配發；設定 IP 時，不論佔用者是否在線都提出告警；BOOTP 拒絕配發時，主畫面寫出原因。
> 對應需求：需求規格書 3.10 DSC-21～DSC-23（待確認），並修訂 INS-04（3.0.4 步驟 3）、DSC-07、DSC-10。
> 狀態：rev 1，待 PO 逐條簽核。

---

## 1. 事件（2026-11-02，mosa）

| 時間 | 經過 |
| --- | --- |
| 10-07 | 舊的第 1 台「前沿」（`00:01:fc:de:3a:75`）向電腦要 IP，dnsmasq 在租約檔 `/var/lib/misc/dnsmasq.leases` 記下「192.168.10.11 屬於這台」，期限永久（`dhcp-range … infinite`） |
| 11-02 09:40 | 工程人員在設備設定刪除舊設備，新平台的 DL-EN1 plat1（`74:95:A7:15:9B:82`）設為使用中、IP 192.168.10.11 |
| 09:41～10:42 | plat1 每 3～5 秒送一次 BOOTP 請求，dnsmasq 每次回「192.168.10.11 address in use」拒絕，共約 700 次；App 每次重新啟動 dnsmasq 都會重讀租約檔，舊紀錄仍在 |
| 同期 | 主畫面只顯示「偵測不到（timed out）」，設定頁「探頭偵測」逾時；現場看不出原因 |
| 10:41 | PO 以 sudo 刪除租約檔的舊紀錄，App 重新啟動 dnsmasq 後 1 秒，plat1 取得 .11，偵測到 12 支探頭 |

### 1.1 根本原因

1. **租約檔與主機對應是兩份資料**。App 只管主機對應（`dl-en1.hosts`，依資料庫產生）；租約檔由 dnsmasq 自己寫，App 刪除設備、改 IP 都不會動到它。
2. **租約永久有效**，且 dnsmasq 啟動時重讀，所以「重新啟動 dnsmasq」（DSC-07）清不掉。
3. **租約檔由 root 擁有**，App 與工程人員在畫面上都無法處理，只能由有 sudo 權限的人手動刪除。
4. **畫面沒有原因**：dnsmasq 的拒絕只出現在日誌，主畫面與設定頁只看到逾時。

### 1.2 什麼情況會再發生

只要把一個 IP 從 A 設備改給 B 設備，且 A 曾經向這台電腦取得過這個 IP：換新機（刪除舊機後設定新機）、替換（DSC-14）、兩台對調 IP、已停用設備的 IP 給新機（DSC-09）。

## 2. PO 提議與評估（2026-11-02）

PO 原話：「當 App 新增 DL-EN1 時給予 IP，要去查閱 dnsmasq 設定檔，IP 與 MAC 必須對應；若有設備已經佔用 IP 必須要提出告警，不管這個設備有無在線。若 MAC 已經存在設定檔則要更換 IP（來自頁面設定的）。完成設定後重新啟動 dnsmasq。」

| 提議 | 現況 | 本提案 |
| --- | --- | --- |
| 核對設定檔的 IP 與 MAC | 主機對應已依資料庫產生，當天內容正確 | 問題在租約檔 → DSC-21 讓租約檔不再存在 |
| IP 被佔用就告警，不論在線與否 | 資料庫中的使用中／維修中／其他設備重複時禁止（DSC-08）；在線設備以 ARP 探測警告（DSC-10） | DSC-22 補上不在線的佔用者：曾經使用此 IP 的其他設備（含已停用、不明），以及舊租約 |
| MAC 已存在則改為頁面上的 IP | 主機對應已是如此 | 不變 |
| 設定完成後重新啟動 dnsmasq | 主機對應有變更時已重新啟動（DSC-07） | 不變；DSC-21 之後，重新啟動就會清掉記憶體中的舊租約 |

## 3. 設計

### 3.1 DSC-21 dnsmasq 不保存租約

- 安裝包產生的主設定 `/etc/flatness/dnsmasq.conf` 加入 `leasefile-ro`：dnsmasq 不讀、不寫租約檔。已在 mosa 的 dnsmasq 2.90 以 `--test` 確認語法。
- IP 只依主機對應配發：同一 MAC 永遠得到主機對應中的 IP；主機對應改變時 App 依 DSC-07 重新啟動 dnsmasq，記憶體中的租約一併清除。
- 不影響：設備探索（DSC-01，讀 dnsmasq 日誌）、實際使用 IP（DSC-19，ARP）、DL-EN1 本身記住 IP（仍要按 RST）。
- 現有機器：執行一次 `sudo ./installer/setup-bootp.sh`（只重寫主設定，可重複執行）。之後原本的 `/var/lib/misc/dnsmasq.leases` 不再被讀取，不必手動刪除。

### 3.2 DSC-22 IP 佔用告警（不論是否在線）

設定或變更 IP 時，在 DSC-08（資料表衝突，禁止）與 DSC-10（ARP 探測在線設備，警告）之外，另外檢查：

| 來源 | 條件 | 訊息（例） |
| --- | --- | --- |
| 資料表 `lan_device.seen_ip` | 其他任何狀態的設備（含已停用、不明、其他），實際使用 IP 等於此 IP | 「00:01:FC:DE:3A:75（已停用 前沿）最後於 10/07 13:51 使用 192.168.10.11；它仍記得這個 IP，接上網路會衝突」 |
| dnsmasq 租約檔（主設定尚未加入 `leasefile-ro` 時才檢查） | 此 IP 被登記給其他 MAC | 「192.168.10.11 仍被舊租約登記給 00:01:FC:DE:3A:75，BOOTP 會拒絕配發給這台；請維護人員執行 sudo ./installer/setup-bootp.sh」 |

- 兩者都是**警告**：檢查訊息與確認儲存頁列出，不阻擋儲存（與 DSC-10 相同；佔用者可能已不存在）。
- 租約檔可讀（root 擁有、644），App 不寫入。

### 3.3 DSC-23 BOOTP 拒絕配發時寫出原因

- App 已在讀 dnsmasq 日誌（DSC-01）。「DL-EN1 使用中」或「維修中」設備的請求被拒（`address in use`、`no address available`）時：
  - 主畫面該台的探頭方塊與頂端提示：「第 1 台 plat1 拿不到 IP：192.168.10.11 被其他設備佔用（BOOTP 拒絕配發），請洽維護人員」，取代單純的「偵測不到」。
  - 設定頁該台的資訊列：「BOOTP：拒絕配發（address in use），最近 10:30:24」。
  - 日誌只在狀態改變時記一筆（第一次被拒、恢復配發），不每次請求都寫。
- 該設備之後成功取得 IP（日誌出現配發，或 ARP 看到它使用設定的 IP）時，提示自動消失。

1. M1 安裝包：`leasefile-ro`、安裝後檢查。
2. M2 日誌解析與拒絕狀態（DSC-23）。
3. M3 設定頁佔用告警（DSC-22）。
4. M4 文件、截圖、變更紀錄。
5. M5 真機確認（mosa：重跑 setup-bootp.sh 後 IP 對調測試）。
