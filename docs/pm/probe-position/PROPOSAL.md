# 提案：探頭位置改為每個探頭設定第幾排、第幾點

> 表面平整檢查系統的設定與畫面調整。探頭在板子下方的位置，由工程人員在「設備設定」逐一設定「第幾排」「第幾點」，不再由所屬 DL-EN1 的位置與探頭順序推定。
> 對應需求：需求規格書 3.13 探頭位置（POS-01～POS-09，**待確認**）。全部條文簽核前不實作。

## 1. 背景與目標

目前每台 DL-EN1 設定一個位置「第 N 排」（`key` = `row-1`～`row-10`），這台的探頭依 ID 順序由左到右，就當作探頭在板子上的位置。實際安裝時，同一台 DL-EN1 的探頭可能分散在板子不同的排，一排也可能混了不同台的探頭（GT2 放大器串在 DIN 軌上，但感測頭以線材接出，裝在哪裡不受串接順序限制）。這時主畫面與 3D 圖上的位置都會和實物不符。

本提案要做到：

1. 每個探頭各自設定「第幾排」「第幾點」（未定、1～5），預設未定。
2. 量測主畫面依探頭的實際位置排列，作業員看到的排與點就是板子上的排與點。
3. 3D 繪圖依同一位置畫在板子上。
4. 排與點都有名稱（預設「排1」～「排5」、「點1」～「點5」），可修改。
5. 允收標準、校準、BOOTP 不受影響；量測紀錄的識別方式不變，舊資料照常對應。

## 5. 設計

### 5.1 資料

**探頭物件**（`lan_device.dl_en1_config.probes[]`、定義檔 3.7.1）新增兩個選填欄位：

```json
{ "id": 2, "description": "點2", "row": 1, "point": 2, "tolerance": 0.5 }
```

- `row`、`point`：整數 1～5，兩者同時存在或同時省略；省略即未定。存在 JSON 欄位裡，`lan_device` 資料表結構不需要改。
- `description` 仍為必填（1～10 字，3.7.1）。新增探頭的預設值為「探頭 N」（`settings_dialog._on_probe_count`）；第一次設為 DL-EN1 時預先帶入的 4 個探頭（`lan.default_config`，目前為左、左中、右中、右）也改為「探頭 1」～「探頭 4」，讓自動帶入（§5.3）對新設備同樣有效。`installer/dl-en1.json` 是現場提供的設定，名稱不改。
- 升級：既有探頭沒有這兩欄，即為未定，不做自動轉換（POS-A1：不猜位置）。

**排名稱、點名稱**

- 主檔為新資料表（`sql/in-win.sql`，可重複執行）：

```sql
CREATE TABLE IF NOT EXISTS flatness.plate_position_name (
  kind        ENUM('row','point') NOT NULL COMMENT '排／點（POS-03）',
  seq         TINYINT UNSIGNED    NOT NULL COMMENT '第幾排／第幾點（1～5）',
  name        VARCHAR(10)         NOT NULL COMMENT '名稱；預設 排1～排5、點1～點5（POS-09）',
  updated_at  DATETIME(3)         NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (kind, seq),
  CONSTRAINT chk_plate_position_seq CHECK (seq BETWEEN 1 AND 5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci
  COMMENT='板子上排與點的名稱（3.13 POS）';
```

- 沒有資料時以預設名稱顯示；儲存時寫入全部 10 筆（`INSERT … ON DUPLICATE KEY UPDATE`）。App 帳號已有 `flatness.*` 的 SELECT、INSERT、UPDATE 權限，不需要 DELETE。模擬資料庫（`flatness_sim`）不需要這張表（模擬模式不探索、不改設定）。
- **定義檔也帶名稱**：`sync.render` 產生定義檔時，在頂層加入選填欄位 `position_names`：

```json
{ "version": 1,
  "position_names": { "rows": ["前排","排2","排3","排4","排5"], "points": ["點1","點2","點3","點4","點5"] },
  "dl_en1": [ ... ] }
```

  資料庫無法連線時（DSC-06），App 與設備清單一樣沿用磁碟上定義檔中的名稱；定義檔沒有這個欄位時用預設名稱。上傳的定義檔或匯入的設定帶有此欄位時一併套用，沒有時保留目前的名稱。
- **定義檔永遠帶目前的名稱**：`sync.render(devices, net, names)` 一律寫入 `position_names`。`sync.startup` 從資料庫讀設備時一併讀名稱（`store.load_names()`，沒有資料為預設名稱）。`sync.apply(..., names=None)` 的 `None` 表示「名稱不變」：沿用資料庫中目前的名稱寫定義檔，不是省略欄位。所以校準（立即儲存）、刪除、上移／下移等不經過名稱區塊的儲存，產生的定義檔仍保留自訂名稱。
- `initdb`（DEF-10，第一次以 `installer/dl-en1.json` 匯入）：檔案帶有 `position_names` 時一併寫入 `plate_position_name`，沒有時不寫（顯示預設名稱）。

**JSON Schema**（`app/flatness/dl-en1.schema.json`，規格書 3.7.1 內嵌的 Schema 同步更新）：

```json
"position_names": { "type": "object", "additionalProperties": false,
  "properties": {
    "rows":   { "type": "array", "minItems": 5, "maxItems": 5, "items": { "type": "string", "minLength": 1, "maxLength": 10 } },
    "points": { "type": "array", "minItems": 5, "maxItems": 5, "items": { "type": "string", "minLength": 1, "maxLength": 10 } } } }
```

探頭 `probe` 加入 `"row": {"type":"integer","minimum":1,"maximum":5}`、`"point"` 同上，`dependentRequired` 加上 `"row": ["point"], "point": ["row"]`。

**檢查分兩層**（沿用現有分工）：

| 層 | 位置 | 檢查 |
| --- | --- | --- |
| 單台／定義檔 | `bootp.validate`（JSON Schema 與跨欄位規則） | `row`、`point` 範圍 1～5、同時存在或同時省略；定義檔內各台之間 `(row, point)` 不重複（處理上傳的定義檔，只含使用中）；`position_names` 同類不重名 |
| 設定頁全體 | `lan.validate`（現有 `groups` 不可重複檢查） | 「使用中」「維修中」所有探頭的 `(row, point)` 不重複，每個衝突的探頭都標示，訊息以設備稱呼（§5.2）稱呼佔用者，例「排1 點3 已由 第 2 台 中排 點3 使用」（設定頁與 `lan.validate` 同一個格式）；排名稱、點名稱同類不重名、不可空白 |

`lan._entry_issues` 把 `bootp.validate` 的欄位路徑轉成清單訊息，其中的比對式要加上 `row|point`，訊息為「第 N 列（ID n）位置須同時設定排與點，或都設為未定」。上傳定義檔或匯入設定時，若與既有「維修中」設備的位置衝突，由 `lan.validate` 拒絕（與 key、名稱衝突的做法相同）。

**不變的部分**：`inspection_point` 的識別（`device_key` + `probe_id`）、允收標準、校準紀錄、BOOTP 對應檔、`key` 的值與格式。

**量測紀錄保存當時的位置（依 §10 第 1 點的建議）**：`inspection_point` 新增選填欄位 `pos_row`、`pos_point`（TINYINT，NULL 為未定）與 `row_name`（VARCHAR(10)，NULL 為未定）。與 `device_name`、`probe_description` 一樣保存量測當時的值（DEF-08 的延伸），事後改位置或改名稱不影響舊紀錄。要改的地方：`sql/in-win.sql`（`flatness` 與 `flatness_sim` 兩個資料庫都要可重複執行的 ALTER；`flatness_sim.inspection_point` 是 `LIKE` 建的，不會自動跟著加欄位）、`results.to_record`、本機暫存檔（舊格式沒有這三欄時視為 NULL）、`store.write_inspection`、`store.read_inspections`。

### 5.2 顯示名稱

同一台的兩個探頭可能都叫「點2」（分別在不同排），所以畫面、訊息、檔案中稱呼一個探頭時，一律用下面的「顯示名稱」：

| 探頭狀態 | 顯示名稱 | 例 |
| --- | --- | --- |
| 已設定位置 | 排名稱＋空格＋位置名稱 | 排1 點2 |
| 位置未定 | 第 N 台＋空格＋DL-EN1 名稱＋空格＋位置名稱 | 第 2 台 中排 探頭 3 |

同一個畫面或檔案中若有兩個探頭顯示名稱相同（例如工程人員把同一排兩個點的位置名稱都改成「左」），兩者都在後面加「（第 N 台 探頭 id）」。使用處（給作業員看的地方）：結果橫幅（偏高、偏低、設備異常原因）、頂端摘要、3D 標籤與拒絕訊息、Excel 欄位標題與「不合格點」。主畫面方塊本身不用顯示名稱，而是大字位置名稱加小字「第 N 台 名稱」（POS-05）。

設備設定頁說的是「哪一台的哪一個探頭」，不論有沒有位置，一律用「**設備稱呼**」：第 N 台＋空格＋DL-EN1 名稱＋空格＋位置名稱，例「第 2 台 中排 點2」；同一台有兩個探頭位置名稱相同時加「（探頭 id）」。使用處：佔用者標示、位置衝突與其他檢查訊息、確認儲存的變更清單（包含現有的探頭變更行，例 `lan.py` 產生的「探頭 ID n「名稱」…」改為「第 2 台 中排 點2：…」；`tests/test_ui.py` 與操作說明書中依賴此文字的地方在 M2、M5 一併更新）。

### 5.3 設備設定

DL-EN1 詳細區：

- 位置下拉選單改稱「第 1 台」～「第 10 台」（值仍為 `row-1`～`row-10`），欄位標題改為「第幾台」。
- `name` 欄位標題改為「DL-EN1 名稱」。

探頭清單由 5 欄改為 7 欄：

```
 ID │ 位置名稱 │ 第幾排 │ 第幾點 │ 校準狀態          │ 校準 │ 允許誤差
────┼──────────┼────────┼────────┼───────────────────┼──────┼─────────
  1 │ 點2      │ 1    ▾ │ 2    ▾ │ 10-13 15:30 已校準 │ 校準 │ 0.5 ▾
  2 │ 點4      │ 1    ▾ │ 4    ▾ │ 未校準             │ 校準 │ 0.5 ▾
  3 │ 探頭 3   │ 未定 ▾ │ 未定 ▾ │ 未校準             │ 校準 │ 0.5 ▾
```

**選單規則**（佔用的判斷包含整個設定頁目前尚未儲存的編輯，比照現有「第幾台」選單的做法）：

- 「第幾排」選單：1～5 永遠可選。該排 5 個點都已被其他探頭佔用時，選項後面標示「（已滿）」，選了之後「第幾點」沒有可選的點。
- 「第幾點」選單：列出所選排的 1～5，已被其他探頭佔用的點停用並標示佔用者，例「3（已由 第 2 台 中排 點3 使用）」。排為未定時，點的 1～5 都可選（先選點後選排也可以）。
- 改了排之後，若原本的點在新的排已被佔用，點自動改回「未定」，訊息區提示「第 N 列（ID n）排1 點3 已被使用，請重新選擇點」。
- 只選了排或只選了點：該列紅框，訊息區列出「第 N 列（ID n）位置須同時設定排與點，或都設為未定」（與上面 `_entry_issues` 同一個訊息），無法儲存。
- 同時編輯兩個探頭造成重複（例如兩台設備各選了同一個位置）：由 `lan.validate` 在兩個探頭上都標示衝突，無法儲存。

**自動帶入位置名稱**（POS-09）：選定「第幾點」為 k 時，若目前的位置名稱符合下列任一條件，就改成點 k 的名稱：

1. 符合「探頭 N」的格式（新增探頭的預設名稱；N 不必等於目前的 ID，因為刪除中間的探頭後 ID 會重排）；
2. 原本選的是點 j 時，等於點 j 目前的名稱，或等於點 j 的預設名稱「點j」（點名稱改過之後，先前自動帶入的舊名稱仍視為自動帶入）；
3. 編輯中被清空。

都不符合時（工程人員自己取的名稱）不改。點改回「未定」時，位置名稱不變。修改點名稱時，不回頭改已經帶入的探頭位置名稱。

**排與點名稱區塊**：放在設定頁 DL-EN1 清單上方（依 §10 第 2 點的建議）：

```
 排名稱  [排1    ] [排2    ] [排3    ] [排4    ] [排5    ]   恢復預設
 點名稱  [點1    ] [點2    ] [點3    ] [點4    ] [點5    ]   恢復預設
```

名稱 1～10 字，同類不可重名，不可空白；不符合時欄位紅框並列入訊息區，無法儲存。

**預覽與儲存**（EDT-03）：

- 排名稱、點名稱的變更算在「有變更」之內：`Preview` 與 `is_dirty` 要納入名稱比對；只改名稱也可以預覽與儲存（目前 `lan.diff` 只比對設備，只改名稱時會顯示「沒有任何變更」並停用儲存）。
- 變更清單列出位置與名稱變更，例「第 2 台 中排 探頭 1：未定 → 排1 點2」「排1 名稱：排1 → 前排」。
- 設定頁儲存時，只有名稱區塊有變更才傳入 `names`，否則傳 `None`（名稱不變，不寫 `plate_position_name`）。`sync.apply(..., names=)` 在既有的同一個資料庫交易內寫入名稱，再寫定義檔（含 `position_names`）。失敗時名稱與設備一起還原；`MemoryStore` 的交易快照要包含名稱。

### 5.4 量測主畫面

```
┌ 排1 ──┬──────────────┬──────────────┬──────────────┬──────────────┬──────────────┐
│       │ 點1          │ 點2          │              │ 點4          │              │
│       │ 第 1 台 前排 │ 第 1 台 前排 │   （空）     │ 第 2 台 中排 │   （空）     │
│       │ 0.012 mm 合格│ …            │              │ …            │              │
├ 排3 ──┼──────────────┼──────────────┼──────────────┼──────────────┼──────────────┤
│       │ …            │ …            │ …            │ …            │ …            │
├ 未設定位置 ┬──────────────┬──────────────┐
│ 請在設備設定│ 探頭 3       │ …            │
│ 設定探頭位置│ 第 2 台 中排 │              │
└────────────┴──────────────┴──────────────┘
```

- 由上而下為第 1～5 排；沒有任何使用中或維修中探頭的排不顯示。
- 每排固定 5 格，第 k 點在第 k 格。空格為淡色虛線框，不顯示任何數值。
- 排頭為排名稱。
- 「未設定位置」區：位置未定的探頭（含維修中設備的探頭），依第 N 台、探頭 ID 排列，每列 5 格。使用中設備的探頭照常量測與判定，維修中的依 §5.5。全部探頭都已設定位置時不顯示。
- 方塊：大字為位置名稱，下方小字「第 N 台 DL-EN1 名稱」。其餘內容（測量值、標準值、允收、刻度條、設備狀態）不變（UI-04）。
- UI-11 的縮放：以「列」為單位計算，每個位置排算一列，「未設定位置」區每 5 個探頭算一列。例：升級後的 mosa（10 個探頭全部未定）為 2 列。

### 5.5 設備狀態對應

目前狀態掛在 `DeviceRow`（一台一排）。改成依位置排列後，每台 DL-EN1 的狀態對應到它的所有方塊（不論在哪一排或在「未設定位置」區）。維修中設備的探頭也建立方塊（目前維修中只有一個說明框），放在設定的位置或「未設定位置」區。

**方塊**同時符合多個狀態時，依下列優先順序顯示最前面的一個。**頂端提示**與方塊無關：每一種狀態只要成立就各自顯示，互不取代（DSC-20「頂端提示仍顯示」不變）。

| 優先 | 狀態 | 方塊 | 結果橫幅 | 頂端提示 |
| --- | --- | --- | --- | --- |
| 1 | 維修中 | 灰色「維修中」，不量測、不判定，位置保留 | 不列入 | 「第 N 台 名稱 維修中」（灰色，新增 `set_flag("maint")`） |
| 2 | DL-EN1 偵測不到 | 設備異常「DL-EN1 偵測不到」 | 設備異常原因「第 N 台 名稱 DL-EN1 偵測不到」 | 「第 N 台 名稱 偵測不到」（新增 `set_flag("dev")`） |
| 3 | 整台設備異常（本機錯誤、探頭台數超出定義 DEF-06 等，`DeviceStatus.error`） | 設備異常，顯示原因 | 設備異常原因「第 N 台 名稱 原因」 | 併入 `set_flag("dev")`，例「第 N 台 名稱 探頭台數超出定義」 |
| 4 | 探頭無回應、未校準、未設定允收標準 | 只有該探頭，同現在 | 同現在，以顯示名稱稱呼 | 不變 |
| 5 | 量測結果 | 同現在 | 同現在，以顯示名稱稱呼 | 不變 |

**IP 不符（DSC-20）不是方塊狀態，而是附加標示**：該台每個方塊加警示色外框與小標「IP 不符」，方塊內容仍依上表顯示（照常量測，第 4、5 列看得到哪一點有問題）；維修中時小標為「IP 不符・維修中」（同現在）。偵測不到（第 2 列）或整台設備異常（第 3 列）時，方塊不加 IP 不符標示，以設備異常優先（DSC-20，同現在 `DeviceRow.set_down` 的做法）；頂端兩種提示都顯示。結果橫幅不列入；頂端沿用 DSC-20 的提示，文字中的「第 N 排」改為「第 N 台」，與上表任何一列同時成立時仍顯示。

頂端的「維修中」「偵測不到／設備異常」提示各最多列 2 台，其餘以「等 N 台」表示（同 UI-11 的做法）。左側的設備摘要（`sum_text`，例「3 台 DL-EN1、10 個探頭正常」）不變。

### 5.6 3D 繪圖

- 位置：x = 長 ×（點 − 0.5）／ 5，y = 寬 ×（排 − 0.5）／ 5（取代 `plate3d.config.probe_positions` 的平均分佈）。
- 標籤第一行為顯示名稱（§5.2），例「排1 點2」。
- 拒絕順序：先檢查「使用中」設備是否有未定位置的探頭（POS-07），再檢查有效點數（P3D-02）與同一直線（P3D-03）。維修中設備的探頭不參與。
- 拒絕訊息（與 POS-07 一致，第二行為顯示名稱）：

```
無法繪製 3D：有 2 個探頭未設定位置（第幾排、第幾點）。
第 2 台 中排 探頭 3、第 3 台 後排 探頭 1
請工程人員在設備設定設定探頭位置
```

- P3D-03 的「同一直線」判斷不變。5 × 5 格時，探頭都在同一排、或都在同一點（例如第 1～3 排的第 2 點），都是同一直線，所以拒絕訊息改為「無法繪製 3D：所有有效量測點在同一直線上（例如都在同一排，或都在同一點），探頭須分佈在不同的排與點。」（P3D-03 文字修訂，列入 POS-07）

### 5.7 Excel 匯出

- 資料只來自量測紀錄（不讀目前的設定），依 §5.1 保存的 `pos_row`、`pos_point`、`row_name` 排列與命名。
- 測量值欄以（`device_key`、`probe_id`）為一欄，該欄的位置與名稱取當日最後一筆紀錄（與現在取名稱的做法相同；當日移動過位置的探頭依最後的位置排列）。順序：有位置的依（排、點），同一位置當日有兩個探頭時再依 `device_key`、`probe_id`；沒有位置的（未定，或升級前的舊紀錄）排在最後，依 `device_key`、`probe_id`。
- 欄位標題與「不合格點」用顯示名稱（§5.2），名稱取當日最後一筆紀錄。
- 第二工作表（當日標準值）原本的「排」欄改為「第幾台」，另加「位置」欄（例「排1 點2」，未定為「未定」）。
- MAC 欄仍是每台 DL-EN1 一欄，標題改為「第 N 台 名稱 DL-EN1 MAC」。

### 5.8 生命週期與邊界情況

| 情況 | 行為 | 測試 |
| --- | --- | --- |
| 已停用改回使用中（DSC-09），原本的位置已被別的探頭使用 | 位置保留在設定中，`lan.validate` 標示衝突，改掉才能儲存 | 有 |
| 替換（DSC-14） | 新機接手舊機的設定，探頭位置一併接手（`lan` 替換流程複製整個 `config`） | 有 |
| 刪除中間的探頭（ID 依串接順序重排，EDT-06） | 其餘探頭的排、點、位置名稱跟著原本那一列走，不因 ID 改變而遺失（`_on_field_edited` 重建 `probes` 時要帶上 `row`、`point`） | 有 |
| 從備份還原定義檔（UPL-10），備份是升級前的格式 | 沒有位置的探頭變成未定；預覽的變更清單列出「位置：排1 點2 → 未定」，由工程人員確認 | 有 |
| 上傳的定義檔或匯入的設定沒有 `position_names` | 保留目前的名稱 | 有 |
| 資料庫無法連線（DSC-06） | 設備與名稱都沿用定義檔 | 有 |
| 降版：以舊版 App 執行 | 不支援。舊版讀定義檔時不驗證（`definition.load_definition`），主畫面回到一台一排；但舊版用舊 Schema 檢查資料庫中的設定，只要有任何探頭帶 `row`、`point`：啟動時一直顯示「設備設定有錯誤」、設定頁所有立即儲存（校準、刪除、上移／下移）都失敗，而且不只帶位置的那台。如需降版，先在新版把所有探頭位置設為未定再降（`position_names` 與新資料表、新欄位留著無妨）。寫入安裝說明 | 不需 |

## 9. 風險與已知限制

- **最多 25 個位置**：排、點各 5 個。探頭超過 25 個的機台，必有探頭未定，無法使用 3D（POS-07）。目前 mosa 有 10 個探頭。
- **升級後 3D 暫時不能用**：既有探頭全部未定，要等工程人員設定位置才能使用 3D；主畫面也會先全部顯示在「未設定位置」區。這是刻意的（不猜位置），但上線前要安排設定。
- **主畫面改動大**：設備狀態從「一台一排」改為「一台對應多個方塊」，是這次最容易出錯的地方，M3 需要完整測試。
- **`name` 意義改變**：DL-EN1 的 `name`（例「前排」）改為設備名稱，既有資料不改值，但畫面上的意思變了，可能需要工程人員重新命名。
- **不支援降版**：見 §5.8。
- **升級要先跑 SQL**：見 §8 升級順序。
- **資料庫無法連線時看不到維修中的設備**：定義檔只含使用中，資料庫無法連線時主畫面沒有維修中設備的方塊（現有限制，不在本提案改變）。
