# 新機安裝指南：空白 Ubuntu → App 可運行

| 項目 | 內容 |
| --- | --- |
| 讀者 | 設定新站台 PC 的工程人員（可搭配 Claude Code 逐步執行） |
| 目的 | 從**剛裝好的 Ubuntu 桌面**，做到「開機自動登入 → App 自動全螢幕啟動 → 可偵測 DL-EN1」 |
| 範圍 | **OS／環境層**（本文）。App 內的設備、探頭、版面、校準設定見《快速安裝指南》 |
| 適用 | Ubuntu 22.04 或 24.04 **桌面版（GNOME）**；本文指令在 22.04 實測 |

> 《快速安裝指南》從「電腦已裝好 App」開始；本文補的是它之前的那一段。做完本文最後一步後，接著做《快速安裝指南》步驟 1 起。

## 如何搭配 Claude 使用

把這份檔案指給 Claude Code，請它「依《新機安裝指南》把這台從空白 Ubuntu 設定到 App 可運行」。每個階段的指令都可直接複製執行；**三個需要你提供的現場值**（會在文中以 `← 改這裡` 標示）：

1. **網卡對應**：哪個實體埠接公司網路（WAN）、哪兩個接 DL-EN1（LAN）。
2. **sudo 密碼**：安裝與系統設定需要。
3. **GitHub 存取**：clone 公開 repo 不需認證；若要 push 才需 token。

---

## 階段 0　引導：裝好 Chrome + VS Code + Claude（人手動，先做這個）

空白機器上還沒有 Claude，先手動跑引導腳本，之後才能用 VS Code 裡的 Claude 接手後面階段。**不需先 clone**：

```bash
wget -qO bootstrap-tools.sh https://raw.githubusercontent.com/kuohsuming/in-win/main/scripts/bootstrap-tools.sh
bash bootstrap-tools.sh        # 裝 Chrome、VS Code、Claude 擴充(anthropic.claude-code)，並 clone ~/in-win
```

完成後：`code ~/in-win` 開啟 → 側邊欄登入 Claude 擴充(首次用瀏覽器登入，故先裝 Chrome) → 對 Claude 說「依 `docs/manual/新機安裝指南.md` 設定這台」。之後階段 1～7 交給 Claude。

> VS Code 的 `anthropic.claude-code` 擴充自帶 Claude Code runtime，不需另裝 Node 或 `claude` CLI。

---

## 前置需求

- Ubuntu **桌面版**已安裝完成、能進桌面、能上網（WAN 網路線已接）。
- 有 sudo 權限的帳號（本文以此帳號執行 App，稱「App 帳號」）。
- 機器有 **3 個網口**：1 個接公司網路（WAN）、2 個接設備網路（LAN，給 DL-EN1）。

## 階段 1　系統套件與時區

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip mysql-server
# 選配：GitHub CLI（要 push 才需要）
sudo apt install -y gh
# 時區與時間同步（量測時間戳 measured_at 依此；依現場調整時區）
sudo timedatectl set-timezone Asia/Taipei
sudo timedatectl set-ntp true
```

> 用**系統內建的 `python3`**（Ubuntu 22.04 為 3.10、24.04 為 3.12；PySide6 6.11 皆支援），不綁定 3.11，避免新機沒有 deadsnakes PPA 而裝不到。Qt/PySide6 的執行庫由桌面版 Ubuntu 內建，無需另裝。

## 階段 2　取得程式、建立虛擬環境

```bash
cd ~
git clone https://github.com/kuohsuming/in-win.git
cd ~/in-win
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-dev.txt    # PySide6 較大，約數分鐘
```

## 階段 3　網路：WAN 與 設備 LAN（bridge）

### 3.1 找出網卡對應　← 改這裡

```bash
ip -br link | grep -v '^lo'          # 列出網卡（如 enp2s0 enp3s0 enp4s0）
ip -4 route show default              # 預設路由（上網）所在的那張就是 WAN
for i in $(ls /sys/class/net | grep -v lo); do echo "$i carrier=$(cat /sys/class/net/$i/carrier 2>/dev/null)"; done
```

- **WAN**：有預設路由、carrier=1（已接線上網）的那張 → **不要**放進 bridge。
- **LAN**：另外兩張 → 要橋接成 `br-lan`，接 DL-EN1。

### 3.2 填入現場參數

編輯 `installer/site.conf`，設定（範例為本站值，依 3.1 結果調整）：

```
STATION_ID=ST01
APP_USER=                       # 留空＝執行 sudo 的帳號
EQUIP_IF=br-lan                 # 設備網卡＝要建立的 bridge 名稱
EQUIP_BRIDGE_PORTS="enp2s0 enp3s0"   # ← 改這裡：兩個 LAN 實體埠（空白分隔）
PC_IP=192.168.10.1
NET_PREFIX=24
```

> 只有一張設備網卡（不橋接）時，`EQUIP_BRIDGE_PORTS` 留空、`EQUIP_IF` 設該網卡名。

### 3.3 建立 bridge + BOOTP 服務（一次做完）

```bash
sudo ./installer/setup-bootp.sh
```

這會依 `site.conf`：建立 `br-lan` 橋接兩個 LAN 埠並設固定 IP（`step_equip_net`）、安裝並遮蔽系統 dnsmasq、產生只在 `br-lan` 上運作的 BOOTP 主設定與 sudoers（`step_bootp`）。dnsmasq **由 App 啟動**，開機不自啟。

### 3.4 清掉 LAN 埠上多餘的自動連線（若有）

NetworkManager 可能為 LAN 埠建了預設「有線連線」，會和 bridge 從屬設定相衝突：

```bash
nmcli -t -f NAME,DEVICE,TYPE con show      # 看 LAN 埠(enp2s0/enp3s0)是否有非 bridge 的連線
# 若有（例如「有線連線 1」對到 enp2s0），刪掉它，只留 netplan-* 與 WAN：
# sudo nmcli con delete "有線連線 1" "有線連線 2"
```

## 階段 4　持久資料庫（系統 MySQL）

```bash
./scripts/setup-station-db.sh
```

安裝／啟用系統 MySQL、匯入 `sql/in-win.sql`（建 `flatness` 資料庫、資料表、`flatness_app` 帳號）、設定密碼並寫出 `.dev/db-system.env`（真機模式連線資訊，600 權限）。

（選配）先匯入初始 DL-EN1 清單，否則首次啟動 App 時會自動匯入：

```bash
PYTHONPATH=app .venv/bin/python -m flatness.initdb \
  --db-env .dev/db-system.env --def installer/dl-en1.json --equip-net 192.168.10.1/24
```

## 階段 5　桌面捷徑、Dock、開機自動啟動

```bash
./scripts/install-desktop.sh
```

建立桌面捷徑、應用程式選單、**開機自動啟動**（登入後約 3 秒以真機模式 `--real --system-db` 啟動 App）。圖示用 repo 內的 InWin logo（`app/flatness/ui/assets/app-icon.png`，已隨程式帶入）。

釘到 Dock（快捷列）：

```bash
.venv/bin/python - <<'PY'
import ast, subprocess
cur = subprocess.run(["gsettings","get","org.gnome.shell","favorite-apps"],capture_output=True,text=True).stdout
fav = ast.literal_eval(cur) if cur.strip() else []
if "flatness.desktop" not in fav: fav.append("flatness.desktop")
subprocess.run(["gsettings","set","org.gnome.shell","favorite-apps",str(fav)])
print("Dock:", fav)
PY
```

## 階段 6　Kiosk：自動登入、不鎖屏、不睡眠

**要在階段 5 之後執行**（install-desktop 會把閒置關螢幕設回 5 分鐘，本步驟改回永不關）：

```bash
./scripts/setup-kiosk.sh
```

設定 GDM 自動登入、關閉鎖屏與螢幕保護、螢幕永不待機（`idle-delay 0`）、不自動睡眠，並遮蔽 systemd 睡眠目標（睡眠會中斷 DL-EN1 連線）。

## 階段 7　重開機驗證

```bash
sudo reboot
```

重開機後應：自動登入 → 約 3 秒 App 全螢幕啟動 → dnsmasq 綁上 `br-lan`、連上系統 MySQL。開一個終端機一鍵驗證（不需 sudo）：

```bash
cd ~/in-win && ./scripts/verify-station.sh
```

全部 ✔ 即為正常。

- `br-lan` 未接線時顯示 DOWN 是正常的；把 DL-EN1 接到任一 LAN 埠後會自動 UP。
- App 日誌 `.dev/flatness.log`、開機日誌 `.dev/autostart.log`。
- 沒接 DL-EN1 時 App 會印「偵測…timed out」屬正常，接上硬體即連上。

做到這裡，OS／環境層完成。接著依 **《快速安裝指南》步驟 1** 設定 DL-EN1、探頭、版面與校準。

## 工廠車間部署強化建議（交給產線前評估）

無人顧的產線站台，建議再做以下強化（非必要，依現場政策決定）：

1. **App 崩潰自動重啟**：目前 App 由 GNOME 登入自動啟動，崩潰後要到下次登入才會起。建議改為 **systemd 使用者服務 `Restart=always`**（看門狗），崩潰數秒內自動拉起。需求規格以登入自動啟動為準，是否改採服務由 PO 決定。
2. **關閉自動更新／自動重啟**：`unattended-upgrades` 預設開啟，可能在產線時間自動更新甚至重開機。建議關閉自動重啟或整個停用：
   ```bash
   sudo systemctl disable --now unattended-upgrades    # 或只關自動重啟：改 /etc/apt/apt.conf.d/50unattended-upgrades
   ```
3. **工程人員密碼**：`run-dev.sh` 預設以 `1234` 產生 `.dev/config.toml`。產線建議改為實際密碼：
   ```bash
   HASH=$(.venv/bin/python -c 'import hashlib;print(hashlib.sha256(b"新密碼".encode()).hexdigest())')
   sed -i "s/^engineer_password_sha256 = .*/engineer_password_sha256 = \"$HASH\"/" .dev/config.toml
   ```
4. **時間同步**：量測時間戳 `measured_at` 依系統時鐘；確認 `timedatectl` 顯示正確時區且 `NTP service: active`（階段 1 已設）。
5. **UPS／斷電**：量測中斷電，App 以本機暫存 buffer 保護資料（DAT-04）；仍建議站台配 UPS。

## 本站實際值（參考範例，2026-11-19 設定）

| 項目 | 值 |
| --- | --- |
| OS | Ubuntu 22.04，Python 3.11，MySQL 8.0 |
| WAN | `enp4s0`（port3），NetworkManager 自動 DHCP |
| LAN | `br-lan` = `enp2s0`(port1) + `enp3s0`(port2)，`192.168.10.1/24` |
| App 帳號 | `in-win`，repo 於 `~/in-win` |

## 疑難排解

| 症狀 | 處理 |
| --- | --- |
| `br-lan` 建好但沒有 IP／沒上線 | 檢查 `sudo netplan get bridges`；LAN 埠沒接線時 DOWN 正常，接線即 UP |
| 再次執行 `setup-bootp.sh` 後 bridge 被破壞 | 確認 `site.conf` 有設 `EQUIP_BRIDGE_PORTS`（本專案 2026-11-19 起支援；舊版不支援 bridge） |
| 重開機後 WAN 不通 | WAN 不在 `60-flatness-equipment.yaml` 內，由 `01-network-manager-all.yaml` 自動管理；勿把 WAN 埠放進 `EQUIP_BRIDGE_PORTS` |
| App 沒自動啟動 | 看 `.dev/autostart.log`；確認 `.dev/db-system.env` 存在、`setup-bootp.sh` 已跑、已自動登入 |
| dnsmasq 沒綁 br-lan:67 | 確認 App 在跑；`sudo ss -lunp \| grep 67`；bind-dynamic 會等 `br-lan` 可用才服務 |
| 螢幕還是會關／鎖 | 確認 `setup-kiosk.sh` 在 `install-desktop.sh` **之後**執行 |
